# DS-101 — Refine the DutchyAgent header and conversation alignment

Status: Resolved in 1.0.30 · 2026-11-09

## Problem

The app name, provider label and large actions compete in one left-packed row.
Their vertical alignment is uneven, while centered conversation names make
the sidebar harder to scan.

## Remediation

Separate app identity from right-aligned actions. Use a muted provider badge,
a compact New chat action and a named settings icon. At narrow widths, retain
both actions as named icons. Preserve tab order, tooltips, shortcuts and drawer
focus return. Add padded text alignment to Button with its centered default
unchanged, then left-align the full-width conversation rows. Verify real
geometry, keyboard actions, long titles, themes/scales, native rendering and
all required Rust checks.

## Resolution

Implemented the compact, responsive header in a focused example module. The
provider badge aligns with the title; actions sit on the right in reading/tab
order. Sidebar names now share a padded left origin, retaining native
truncation and complete accessible names. Button's additive `text_align`
builder also keeps loading spinners aligned with their label group.

Geometry and keyboard regressions pass across 480/560/1160-point layouts,
both themes and 1x/1.5x/2x scales. Nine intended Agent snapshots changed;
existing component snapshots are unchanged. Native macOS Retina light/dark
inspection confirms alignment, long-title truncation, tooltips, drawer opening
and Escape focus return. The temporary preview was closed and removed.

All 21 local gates pass, including 630 all-feature tests, 406 minimal tests,
three strict Clippy profiles, docs, feature/MSRV/WASM, native builds and actual
archive inspection. See [verification](../verification-dutchy-agent-shell.md).
No dependencies, version bump, commit or push were added. Native resizing and
screen-reader output remain unverified; narrow layouts/accessibility use kittest.
