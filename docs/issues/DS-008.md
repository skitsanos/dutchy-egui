# DS-008 — Add statistics and empty states

Status: Resolved · 2026-11-06

## Problem

Application essentials need readable KPI values, explicit change interpretation,
and useful guidance when content is absent. Responsive groups must retain metric
identity, and empty-state actions must remain accessible and application-owned.

## Remediation

Add formatted stats, independent trend direction/sentiment, four surfaces,
responsive grids/compact rows, and detailed context. Add generic/search/table/
dashboard empty states with heading metadata, decorative icons, wrapping guidance,
independent actions, and optional polite announcements. Verify identity, keyboard
operation, disabled controls, narrow geometry, and rendering across themes/scales.

## Resolution

Implemented on `ticket/stats-empty-states` (1.0.4), without new dependencies.
Stat/StatsGrid preserve host-formatted values and explicit direction/sentiment,
four surfaces, responsive/compact layouts, and detailed context. Metric identities
survive reflow. EmptyState provides four patterns, independent native actions,
disabled states, headings, decorative icons, and optional status announcements.
The host owns replacement content and its focus destination.

All 65 integration tests and one doctest pass; all required Clippy configurations
pass. Tests cover formatting, trend context, reflow/identity, focus during guidance
and width changes, keyboard/action independence, disabled parents, bounds, and
the example's refresh/create/clear/reset workflows. Reviewed light/dark rendering
at 1x/1.5x/2x, narrow layouts, and native macOS names/values/actions/focus.
See the [guide](../stats-empty-states.md) and
[verification](../verification-insights.md).

Source-palette contrast remains in DS-003. Table empty states supply the body,
without a data-table implementation. Running screen-reader, Windows/Linux GUI,
and minimum-toolchain validation remain outstanding. Tooltips/layout helpers are
the remaining application essentials.
