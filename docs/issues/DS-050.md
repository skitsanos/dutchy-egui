# DS-050 — Slider focus depends on preceding siblings

Status: Resolved locally · 2026-11-07

## Problem

Inserting a sibling before a focused slider lost keyboard focus despite an
unchanged host-supplied ID. The native slider's automatic child ID inherited
the parent's changing sequence through `push_id`.

## Remediation

Create a scope with a persistent ID derived from the host key, then compose
egui's slider inside it. Keep native slider input and accessibility behavior.

## Resolution

`tests/primitive_lifecycle.rs` reproduced the lost focus before the change and
now verifies retained focus and keyboard edits after insertion. The segmented
control passes the same check without implementation changes. Native Tab into
Volume and Right from 40 to 45 also updated the host summary correctly.
