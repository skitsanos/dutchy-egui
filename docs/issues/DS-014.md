# DS-014 — Implement hierarchy and page navigation

Status: Resolved for this step · 2026-11-06

## Problem

The interaction milestone lacked breadcrumbs and pagination. Applications needed
sharp, accessible navigation patterns with explicit current-page semantics,
reachable deep paths, bounded page ranges, and host-owned route/data behavior.

## Remediation

Implement keyed breadcrumb destinations, slash/chevron separators, icon roots,
a muted bar, and a host-controlled collapsed-ancestor menu using the existing
Dropdown. Implement numbered/ellipsis and compact pagination with endpoint,
empty, invalid-range, disabled, and large-count handling. Keep routing and data
loading in the host and use shared geometry/palette/type tokens.

## Resolution

Version 1.0.8 adds `Breadcrumbs`/`BreadcrumbItem` and `Pagination`, plus public-API
showcase pages. Breadcrumbs return typed destinations and mark the last item
current without making it interactive. Hidden ancestors retain keyboard menu
behavior. Pagination returns page requests, bounds its page window, and keeps
numbered control identities stable after the host applies navigation. Native
current-page metadata, names, focus, and disabled behavior are preserved.

Interaction regressions cover activation, current/disabled items, collapsed menu
navigation/dismissal, host-owned state, keyed focus, narrow reflow, and arithmetic
boundaries. Rendering review corrected allocation before wrapping scopes, hidden
label layout for icon-only breadcrumbs, and compact-summary vertical alignment.
Theme/scale snapshots and native evidence are recorded in the
[verification record](../verification-navigation.md).

No dependencies were added. Routing, fetching, responsive collapse decisions,
page-size/jump controls, and focus after external removal remain host concerns.
The native focusable current-page button intentionally differs from the web
component's noninteractive active span. Broader platform and screen-reader
acceptance remain explicit limitations.
