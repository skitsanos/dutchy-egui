# DS-023 — Make pending images visibly communicate loading

## Problem

The pending image surface used only a subtle skeleton pulse. Slow image URLs
could therefore look like empty or stalled content, particularly when reduced
motion made the fill static.

## Remediation

Compose the shared square Spinner into the existing reserved placeholder, with a
centered “Loading image” label and a named busy ProgressIndicator role containing
the image's alternative text. Keep the image's own busy metadata. Use shared
geometry/colors/motion and clip the child UI to the image bounds.

Use indeterminate feedback because providers may omit a reliable total byte
count. Retain static feedback with reduced motion. Omit the label/spinner as
space shrinks, stop animation while clipped, and remove the indicator on ready
or failed status. Preserve image dimensions, captions and expansion controls.

## Resolution

Implemented locally for 1.0.13. Focused tests compare animated/static paint and
repaint scheduling, check busy semantics and completion/failure removal without
layout shift, and exercise tiny placeholders. A deliberately slow local HTTP
response retains the named spinner until its texture is ready. Updated media
baselines cover light 1x, dark 1.5x and purple 2x. Native inspection confirmed
rotation, reduced-motion static feedback and removal when the host supplied the
loaded image. No new dependency was needed for the animation.

See [verification](../verification-url-images.md). Download percentages are not
exposed by this integration; this indicator communicates ongoing work.
