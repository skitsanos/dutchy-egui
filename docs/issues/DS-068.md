# DS-068 — Secondary toggles paint the same on and off state

Status: Resolved in 1.0.24 · Priority: P2 · 2026-11-08

## Problem

`ToggleButton::variant(ButtonVariant::Secondary)` is supported by the public
builder, but its off-state uses Secondary and its pressed state also chooses
Secondary in `actions::core::visuals`. There is no additional pressed marker.
The control therefore looks identical before and after toggling. The shared
renderer also serves Toolbar toggle items with this variant.

An isolated harness kept one named control and ID, changed its host bool from
false to true, verified `Toggled::True` in AccessKit, and compared the output:
all three painted shapes were identical. The value/accessible state changes;
a sighted user gets no state indication. DS-064 fixes the default Outline hover
case but its regression does not cover the Secondary variant.

## Remediation

Define a distinct off/on treatment for every supported toggle variant, using
shared tokens and retaining hover, disabled and focus feedback. Alternatively,
explicitly constrain the toggle variant API and document that constraint.
Add same-control state comparisons across all variants, standalone and toolbar
forms, light/dark themes, and hover/disabled states.

## Resolution

A pressed Secondary toggle gains a flat accent edge from the shared action
tokens. Its fill and existing hover/focus behavior remain intact; the shared
renderer applies the same treatment to Toolbar items. Host values, widget
identity and AccessKit toggled state are preserved.

`tests/toggle_variants.rs` compares actual on/off shapes for every public
variant, standalone and toolbar forms, enabled/disabled and hovered/resting
states at light 1x, dark 1.5x and Blue 2x. The Secondary case failed before
the fix. Three new rendering baselines pass, and native click/Space checks
confirmed both states in the showcase. See
[current verification](../verification-fixes-markdown.md).
