# DS-043 — Data table: duplicate-key repaint loop, unbounded measurements, header drift

Status: Resolved for the defects · 2026-11-07

## Problem

- Row cell identities derive from the host key
  (`root.with(("row", key))` in `src/widgets/table/row.rs`), and cell height
  measurements are stored per row identity in `ctx.data`
  (`src/widgets/table/heights.rs`). Two rows with the same key share one
  entry; when their natural heights differ, each row's `save` sees a change
  and requests a discard or repaint on every pass, forever. `docs/data-tables.md`
  requires unique keys but does not describe this failure mode, and egui's
  duplicate-id warning does not fire for the hover-sense cell scopes.
- Height measurements are inserted per row identity and never removed (no
  `remove_temp` in the table module). Paging or filtering through many
  distinct keys grows memory for the lifetime of the context.
- Header typography: labels use the Display face through `Text::heading`
  and 0.025 em tracking (`src/widgets/table/header.rs`); the live `th` uses the
  body face with 0.05 em tracking. The `Muted` surface paints muted-foreground
  text while the documented muted header keeps the foreground; the sort glyph
  is a single chevron at full opacity (active in primary) where the reference
  draws a double arrow at 30 % opacity, rotated for descending.
- Rows and checkboxes are named by display index ("Row 3", "Select row 3"),
  so names change under sort and filter, and the host cannot name rows by
  record; the viewport is a `Group` where the spec asks for a region.
- Minor: the stripe blend follows the live 30 % rather than the documented
  50 % without saying which source wins; the empty body adds an inbox icon
  absent from both references; the guide's usage example renders 16-point
  cells against the reference's 14.

The vertical-centering mechanism was traced: offsets never feed back into the
measured natural height, rounding cannot oscillate at the 1/32-point grid, and
convergence within two passes is covered at 1x by the kittest run limit; at
1.5x and 2x the tests only step frames.

## Remediation

Detect duplicate keys per pass (debug assertion or a one-shot warning) and
key measurements by position when duplicates occur; evict measurements for
rows absent from the current view. Use the body face and `Tracking::Wider`
for headers, keep foreground text on the muted header, and adopt the
double-arrow glyph with the documented opacities, then refresh the table
baselines. Let hosts supply row names and use the region role for the
viewport. Record the stripe source and the empty-body icon as decisions.

## Resolution

Fixed in 1.0.16. Row scopes are computed once per pass; a repeated key receives
an occurrence salt so duplicate rows keep separate identities, widget IDs, and
measurements, and `heights::evict_stale` removes the measurements of rows that
left the view at the end of each pass. `tests/data_tables.rs` asserts that a
table with duplicate keys requests no further repaints and that paging through
new keys does not grow the context's temporary data. Header labels now use
the bold body face with `Tracking::Wider`, the muted header keeps foreground
text, and the sort glyph is the live double arrow at 30 % opacity, full strength
and rotated for a sorted column (`tests/data_tables.rs`); `docs/data-tables.md`
records the live stripe blend and the port's empty-body glyph. Host-supplied row
names and the region role for the viewport remain open.
