# DS-081 — Tab from a menu attached to a host-drawn button stays on the button

Status: Open · Priority: P2 · 2026-11-09

## Problem

`Dropdown::show_for` documents that Tab "closes the entire menu tree and
follows the button's host tab order". In the review copy of the richer-menus
work (DS-073 to DS-076), a menu attached to a plain egui button closes on Tab
but leaves focus on that button; the following host control is not focused, so
a keyboard user needs a second Tab. Reproduced in a harness: a "Commands"
button with an attached two-item menu and a "Next control" button 360 points
to its right. A click opens the menu with the first row focused; Tab closes it;
"Commands" reports focus and "Next control" does not.

Cause as read: the Tab exit requests focus on the trigger and asks egui to move
focus forward, but a host-drawn trigger registered its interest in focus before
the menu rendered, and egui only hands focus onward when the focused widget
registers later in the pass. MenuBar and Toolbar route Tab before drawing their
own triggers and are unaffected.

## Remediation

Make the forward move happen where egui can honor it for attached triggers
(for example by deferring the move to the next pass or by routing Tab before
the host draws, as the bar and toolbar do), or document the actual behavior.
Add a regression test with a host-drawn trigger followed by a host control, in
both Tab directions.

## Resolution

Open. Found during the
[independent review](../verification-review-ds073-076.md); the fix belongs in
the richer-menus work before release.
