# DS-081 — Tab from a menu attached to a host-drawn button stays on the button

Status: Resolved in 1.0.26 · Priority: P2 · 2026-11-09

## Problem

`Dropdown::show_for` documents that Tab "closes the entire menu tree and
follows the button's host tab order". In the richer-menus work
(DS-073 to DS-076), a menu attached to a plain egui button closes on Tab
but leaves focus on that button; the following host control is not focused, so
a keyboard user needs a second Tab. Reproduced in a harness: a "Commands"
button with an attached two-item menu and a "Next control" button 360 points
to its right. A click opens the menu with the first row focused; Tab closes it;
"Commands" reports focus and "Next control" does not.

Cause as read: the Tab exit requests focus on the trigger and asks egui to move
focus forward, but a host-drawn trigger registered its interest in focus before
the menu rendered, and egui only hands focus onward when the focused widget
registers later in the pass. MenuBar and Toolbar route Tab before drawing their
own triggers and are unaffected.

## Remediation

Make the forward move happen where egui can honor it for attached triggers
(for example by deferring the move to the next pass or by routing Tab before
the host draws, as the bar and toolbar do), or document the actual behavior.
Add a regression test with a host-drawn trigger followed by a host control, in
both Tab directions.

## Resolution

`Dropdown::show_for` now marks its trigger as already drawn. On Tab, the popup
closes, focus returns to the trigger and the move in the key's direction is
stored; the shared popup-focus plugin applies it at the start of the next pass,
before the host draws the trigger, so egui's own traversal reaches the next or
previous host control. Dropdowns that draw their own trigger, MenuBar and
Toolbar keep their same-pass exit. `tests/menu_tab_events.rs` adds the attached
surface to the raw-event direction and Ctrl+Tab tests and a root-level test of
Tab and Shift+Tab across all four surfaces; the attached cases failed before
the change and pass after it. After the three fixes, `cargo fmt --all --check`,
520 all-feature and 369 minimal-feature tests, all three Clippy configurations,
strict rustdoc, the all-feature WASM check, the 1.95 MSRV check and the
showcase build pass on 2026-11-09, and no rendering baseline changed. Native
behavior was not re-checked.

Found by the independent review of DS-073 to DS-076.
