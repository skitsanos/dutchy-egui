# DS-105 — Public types can only grow in major releases

Status: Resolved, unreleased (planned for 1.1.0) · Priority: P2 · 2026-11-10

## Problem

The [versioning policy](../versioning.md) keeps Dutchy on 1.x. Under Cargo's
SemVer rules, a new variant on a public enum, or a new field on a struct whose
fields are all public, breaks host code. No public type carried
`#[non_exhaustive]`, so a centered `ToastPosition`, a new `OverlayOptions` flag
or a new `Icon` would each need 2.0.0. Eight enums exposed
`ALL: [Self; N]`, whose length changes with a new variant. Hosts could build
some option structs only as literals, and a host highlighter had no other way
to create a `CodeSpan`. Nothing stopped a later type from arriving unmarked.

## Remediation

Apply the [versioning policy](../versioning.md):

- Mark 66 enums and 43 all-public structs, and keep the listed 11 exhaustive.
- Turn the `ALL` arrays into slices.
- Add setters to `OverlayOptions` and `UrlImageOptions`, plus
  `ScribbleExportOptions::new` and `CodeSpan::new`.
- Update the examples, tests and guides.
- Add `scripts/check_api.py` to `scripts/check.sh`. It fails on an unmarked
  type that isn't on the keep list, and on a keep-list entry that is stale or
  marked.

New tests must fail first, and a changed snapshot counts as a fault.

## Resolution

Before any type was marked, the check flagged exactly the 109 types that were to be marked. Its
first draft misread generic defaults (`<T = ()>`) and also flagged `Toast`,
`ToastQueue` and `Toasts`, which have private fields. It now parses generics,
and it fails on any struct it can't parse. A probe with a marked `Mode` and a
new all-public struct fails as designed.

`tests/api_extensibility.rs` failed to compile before the API existed. Its
highlighter test also fails when the highlighter is removed, so it checks the
colors that are actually painted.

The compiler found more sites than an earlier text search:

- 27 option literals, not 21: eight in `tests/scribble_model.rs` used an
  alias.
- Two `SearchState` literals, now a helper that assigns `open`; Clippy accepts
  it.
- One `MarkdownLink`, which the test now compares by field.
- Six wildcard arms. One is for `ToastDismissal` on the notifications page,
  which the text search missed. `StepperState` needed none.
- 24 loops over `ALL`.

The modal, image, URL image, Scribble export and Markdown guides use the new
API.

`scripts/check.sh` passes:

- 647 all-feature and 411 minimal tests; 12 with bundled fonts only and 48 with
  the Markdown parser only.
- Three strict Clippy profiles, rustdoc, WASM, MSRV 1.95 and the examples.
- The package inspector, on 432 files.

No snapshot changed; kittest covers both themes at three scales. No native run
was made.

The version stays 1.0.30 until the authorized 1.1.0 release.
`cargo-semver-checks` joins CI after the first crates.io release.
