# DS-021 — Add images, galleries and lightboxes

Status: Resolved for this step · 2026-11-06

## Problem

The advanced milestone had no reusable image, caption, gallery or fullscreen
viewer. Applications needed meaningful alternatives, stable fitting and keys,
loading/failure feedback, keyboard expansion/navigation and modal focus handling
without moving media I/O or durable selection into a helper library.

## Remediation

Build sharp image presentation on egui's source/loader pipeline, keyed responsive
thumbnails and a native modal viewer bound to host selection. Reuse shared tokens,
loading motion and overlay focus/dismissal helpers. Keep decoding, networking,
cache lifetime and retry execution with the host.

## Resolution

Version 1.0.13 adds `Image`, aspect/fit/status/response types, `GalleryItem`,
`Gallery` and `Lightbox`. Images support intrinsic/fixed aspects, contain/cover,
caption/source, explicit busy/error presentation and independent expand/retry
controls. Galleries return stable opening keys; lightboxes bind host selection,
skip disabled items, support optional wrapping, preserve missing selections and
return focus after dismissal. The initial media core added no runtime dependency; optional URL integration
followed in [DS-022](DS-022.md).

Keyboard focus reveals lazy gallery items; pending/error expansion remains
reachable. Viewer Left/Right/Home/End navigation and Page Up/Down caption
scrolling retain Close. Rendering review corrected inherited grid spacing around
captions and constrained credits to the image width. Hidden-close heading focus
now has an explicit accessible name. Source geometry/controls are tokenized.
Caption/source text also inherits inverse-card text colors while image error
feedback retains its own surface; rendered checks cover both font configurations.

Interaction, geometry, loader, texture-pixel, host-workflow and theme/scale tests
cover these behaviors. The showcase uses original raster illustrations, a
deliberately pending host loader and explicit retry handling. Native checks ran
on macOS only, without an active screen reader; Windows/Linux GUI, browser
WASM and real codec/network integrations remain unverified.

Without `url-images`, URI/encoded bytes require a host-installed loader; additional
codecs/file access are not bundled. Collections are nonvirtualized. Zoom/pan, slideshows, swipe/masonry,
drag reorder, downloads and animated-format acceptance are outside this step.
File selection/drop zones and Scribble/export remain planned advanced work.
