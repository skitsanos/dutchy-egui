# DS-072 — Documentation still described the 1.0.24 work as unreleased

Status: Resolved in 1.0.25 · Priority: P3 · 2026-11-08

## Problem

Release 1.0.24 (`4f0cb55`) shipped the action controls, Markdown and CodeBlock,
but several documents kept their pre-release wording. The component guide
`docs/actions-toolbars.md` ended with "This work is Unreleased after the 1.0.23
repository push." The branch qualification record for Markdown said integration
onto main "is Unreleased", and the actions and review records had no pointer to
the release that shipped their findings. Fifteen ledger entries (DS-045, DS-046
and DS-049 to DS-061) still read "Resolved locally" although their fixes shipped
between 1.0.18 and 1.0.23, while newer entries say "Resolved in <version>". The
Markdown showcase page used the kicker "Content / Markdown" where every other
port addition uses "Native additions / …" after DS-065. The IDE folder `.idea/`
was untracked but not ignored, so it appeared in every status listing.

Found during the independent post-push verification of 1.0.24; see the
[release record](../verification-release-1.0.24.md).

## Remediation

State the shipping release in living documents. Add a one-line pointer to the
release record at the top of historical records instead of rewriting their
dated findings. Normalise ledger statuses to the release that carried each fix,
taken from the CHANGELOG sections. Use the shared "Native additions" kicker on
the Markdown page. Ignore `.idea/`. Record the independent verification in the
release record.

## Resolution

`docs/actions-toolbars.md` now says the work shipped in release 1.0.24.
`docs/verification-markdown.md` points to the combined and release records;
`docs/verification-actions-toolbars.md` and `docs/verification-review-1.0.23.md`
open with a pointer to the 1.0.24 record. Ledger statuses: DS-045 → 1.0.18,
DS-046 → 1.0.19, DS-049 to DS-054 → 1.0.20, DS-055 → 1.0.21, DS-056 and DS-057 →
1.0.22, DS-058 to DS-061 → 1.0.23. The Markdown page kicker reads "Native
additions / Markdown"; no test or baseline depends on the kicker text.
`.gitignore` excludes `.idea/`. The release record gained an "Independent
post-push verification" section. After the edits, `cargo fmt --all --check`,
490 all-feature and 342 minimal-feature tests and all three Clippy
configurations pass, and the documents have no broken relative links. The
release gates are recorded in [the 1.0.25 record](../verification-release-1.0.25.md).

Commit trailers in the public history of `684a840` and `facb01c` are left
unchanged; rewriting pushed history is out of scope.
