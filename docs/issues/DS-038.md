# DS-038 — Focused controls in file rows, images, and toasts re-request scrolling every frame

Status: Resolved · 2026-11-07

## Problem

DS-026 fixed canvases and toolbars that called `scroll_to_me` on every frame
while focused, so manual scrolling snapped back. The same pattern remains in
three places:

- `src/widgets/upload/rows.rs`: the Remove/Cancel control calls
  `scroll_to_me_animation` whenever `response.has_focus()`, with no clip
  check at all.
- `src/widgets/media/render.rs`: expand and retry controls call it whenever
  they have focus and lie outside the clip rect. The control takes focus on
  pointer click and regains it when a lightbox closes, so "click Expand,
  close the viewer, wheel-scroll the page" pins the thumbnail.
- `src/widgets/toast/render.rs`: a focused toast control outside the clip
  rect re-requests scrolling each frame.

egui's `ScrollArea` computes a nonzero delta whenever the target lies outside
the clip rect, so each frame undoes the user's wheel or scrollbar input. The
File Uploads showcase page renders inside a vertical `ScrollArea`, so Tab to a
row's X and then scrolling reproduces it. Scribble, menus, steppers, and
overlay content already gate the request on `gained_focus()` or an activation.

## Remediation

Apply the DS-026 rule: reveal on `gained_focus()` or a handled activation, not
on retained focus. Add scroll-area regressions for a focused file-row action,
a focused image control after closing the lightbox, and a focused toast
control, mirroring `tests/scribble_scrolling.rs`.

## Resolution

Fixed in 1.0.16 with a shared rule in `interaction::reveal_focused`: a focused
control is revealed when it gains focus or when layout moves it relative to its
container's content origin; user scrolling moves the origin by the same amount
and never triggers it. File-row actions, image expand/retry controls, toast
controls, and the data table's body and header reveals use the helper. The
table body additionally ignores focus that sits inside a sticky header cell,
because scrolled row rectangles overlap the header area and previously pulled
the body up by one row per frame when a sort control had focus.
`tests/focus_scrolling.rs` and `tests/table_geometry.rs` scroll away from a
focused control and assert that the scroll position is kept; the gallery
reflow test still asserts that a moved control is revealed once.
