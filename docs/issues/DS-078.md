# DS-078 — Scroll areas painted egui's edge fade gradient

Status: Resolved in 1.0.26 · Priority: P2 · 2026-11-09

## Problem

egui 0.37 fades clipped `ScrollArea` content: `Style::spacing.scroll.fade`
defaults to a 20-point gradient at half strength, blended from the surface
background toward transparent wherever more content lies beyond a visible
edge. `Theme::style` kept that default, so every Dutchy scroll surface showed
the gradient: showcase pages, Modal and Drawer bodies, dropdown and command
palette result lists, data tables, toast stacks and Markdown documents. The
[reference decisions](../reference.md) state that no gradients are
introduced, and the web system clips content with a hard edge.

Found while building the DutchyTodo example, which zeroed the fade in its own
theme setup as a workaround. A 400-point fill inside a 120-point scroll area
in the test harness reproduced it: the first row inside the viewport read
`[249, 177, 125]` instead of the Orange primary `[249, 116, 21]` on a light
surface.

## Remediation

Set `spacing.scroll.fade.strength` to zero in `Theme::style`, which `apply`
installs for both egui themes, so one change covers every scroll area without
per-widget code. Cover it with a style-level test across all accents, modes
and motion settings, a test that `apply` installs the zeroed fade for both
egui themes, and a rendering test that samples a column through clipped
content at 1x light and 2x dark and expects the flat fill at both edges.
Record the decision in the reference and getting-started pages. Remove the
example's local workaround when its branch merges.

## Resolution

`Theme::style` zeroes the fade strength. `tests/scroll_fade.rs` holds the
three tests; all failed before the change (strength 0.5, blended edge pixels)
and pass after it.

The Markdown narrow baseline (`tests/snapshots/markdown-narrow.png`) changed
in the last twelve points of its wide table, where the horizontal scroll
area's right fade had lightened the header band, the row rules and the ends of
the last column; the regenerated image differs nowhere else, and no other
snapshot changed. After the change, `cargo fmt --all --check`, 493 all-feature
and 345 minimal-feature tests and all three Clippy configurations pass, and the
documents have no broken relative links. The DutchyTodo example's local
`scroll.fade` workaround becomes redundant once both branches merge.
