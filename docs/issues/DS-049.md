# DS-049 — Focused typed controls accept steps while becoming disabled

Status: Resolved in 1.0.20 · 2026-11-07

## Problem

Number and date inputs processed Up/Down before their editor released focus when
the host disabled them. Time inputs had the same gap when their parent became
disabled. An already open date calendar also remained visible after disabling.
The original suite passed; lifecycle regressions reproduced these transitions.

## Remediation

Require both enabled UI and editor focus before consuming a typed step. Keep
the existing read-only and per-control guards. A disabled date picker closes
its popup without committing a date.

## Resolution

`tests/primitive_lifecycle.rs` checks own and parent disable transitions for all
three typed controls and closing an open calendar. Host values remain unchanged.
A covering-modal regression also passes. Native entry and calendar dismissal
were checked in the rebuilt showcase. See the follow-up verification report.
