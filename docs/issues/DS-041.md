# DS-041 — Stale release statements and over-broad evidence in the ledger

Status: Resolved · 2026-11-07

## Problem

Several records describe a state that no longer holds or cite evidence that
does not support the full claim:

- DS-022 ends with "No commit, push or registry publication was performed for
  1.0.13", and `docs/verification-url-images.md` says 1.0.13 "remains
  uncommitted and unpushed". Release 1.0.13 is on main as `c4a728d`
  (`docs/plan.md` says so too). `docs/url-images.md` still pins
  `version = "1.0.13"` while the crate is 1.0.15.
- DS-022 to DS-026 have no `Status:` line, unlike DS-001 to DS-021.
- DS-017 cites `target/visual-proof/confirmation-width-checks.log`. The
  directory is a generated artifact that the post-push cleanup removes; no
  such log exists now. DS-017 also describes a prior "default 448-point
  dialog" state, but the showcase and the Medium width both arrived in the
  single commit `8132fac`, so that state was never committed.
- DS-019 says the "live plain/inverse treatments" differed from the documented
  muted header; the inverse header comes from the documented striped example,
  not the live component, which has only the plain header.
  `docs/data-tables.md` states this correctly.
- DS-020 says "Three regression tests assert actual child centers at
  1x/1.5x/2x"; only one test in `tests/table_alignment.rs` iterates the three
  scales, the reflow test runs at 1.5x and the pointer/keyboard test at 1x.
  DS-019 and DS-020 also landed in one commit (`3645d19`), so DS-020's
  "updated" snapshots have no prior baseline in history.
- DS-006 says stable identities "preserve child focus when siblings are
  inserted"; `tests/cards.rs` focuses the card itself, not a child.
- The design-system Markdown and the live components disagree in places
  (badge typeface, outline-badge color, tooltip padding, alert warning hue,
  skeleton period). The port follows the live implementation per
  `docs/plan.md`, but only some of these choices are written down; see DS-029
  and DS-033 for the ones that were missed.

Every historical test count in DS-002 to DS-010 was re-derived from the
release commits and matches (16, 35, 44, 55, 65, 76, 96).

## Remediation

Rewrite the DS-022 and verification-url-images sentences to the pushed state
(or date-stamp them as pre-release notes), bump the `docs/url-images.md`
dependency line, add `Status:` lines to DS-022 to DS-026, replace the DS-017
log path with the committed evidence (tests and snapshots), tighten the DS-019,
DS-020, and DS-006 wording to what the tests assert, and keep evidence
pointers to committed files only.

## Resolution

Resolved on 2026-11-07 with the 1.0.16 fixes. DS-022 and the URL-image
verification record now say they predate the 1.0.13 push, the URL-image guide
pins the current version, DS-022 to DS-026 carry Status lines, DS-017 points at
the committed confirmation test and baselines, and the DS-019, DS-020 and
DS-006 sentences describe what the tests assert. The source-documentation
disagreements are recorded in DS-029 and DS-033 and stay with those entries.

Follow-up verification on 2026-11-07 at 1.0.17 found one further stale sentence
in `docs/data-tables.md`: it still described images, files and Scribble as
future work. Replaced it with links to their implemented component guides.
