# DS-075 — Expanded menu cascades have competing highlights and loose geometry

Status: Resolved in 1.0.26 · 2026-11-09

## Problem

The supplied native screenshot highlights Save document and its Export sibling
simultaneously: keyboard focus remains on one row while pointer hover opens
another. Full-width child menus and a gutter make the cascade feel detached;
child content also starts below its parent's row because of the frame border.

## Remediation

Audit pointer/keyboard ownership, highlighted/open-path states, row typography,
padding, separators and popup anchoring. Prefer familiar desktop navigation
with one active target, quieter parent context, content-sized children and
aligned shared edges. Record why this is preferable to replacing the current
menu with a new navigation metaphor. Verify flipping, clipping, wrapped labels
and accessible interaction across modes/scales and in the native showcase.

## Resolution

Menu input ownership now chooses pointer hover or keyboard focus, with one
accent target and muted open ancestors. Branch typography stays regular so
opening does not reflow labels. Menu bars and cascades share frame edges;
children align with their parent row and measure their content, with a
200-point minimum capped by the configured width and viewport. Inline leaf
activation closes descendants and returns to its root branch.

Seven polish regressions cover ownership, geometry in both directions, wrapped
labels, dismissal and external focus. Nine updated rich-menu baselines span
light/dark and 1x/1.5x/2x; the 119 prior baselines are unchanged. See the
[design decision](../menu-interaction-decisions.md) and
[qualification](../verification-menu-polish.md). All automated gates and the
archive audit pass. Native macOS verification on 2026-11-09 confirmed physical
pointer opening, one active row, quiet ancestors, shared aligned edges and
keyboard transitions in Orange/light and Blue/dark. The task-owned preview
was closed and removed. A drill-down panel remains an opt-in future pattern.
Very narrow windows may overlap cascade levels to keep commands inside the
viewport.
