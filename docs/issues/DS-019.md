# DS-019 — Start advanced components with data tables

Status: Resolved for this step · 2026-11-06

## Problem

The advanced milestone lacked a reusable table for typed application records.
Applications needed aligned custom cells, sorting, selection, narrow overflow and
loading/empty guidance while retaining data, comparisons and actions in the host.
The documented muted header, the documented striped example's inverse header
and the live plain header also differed.

## Remediation

Implement repository-owned, keyed column/row composition with native controls,
explicit surface/density variants, shared tokens, constrained scrolling, semantic
table metadata and host-owned requests. Compose existing input, pagination,
badge, skeleton and empty-state primitives in an application example.

## Resolution

Version 1.0.12 adds `DataTable`, typed column/sort/selection/response types, fixed
or flexible column minima, alignment, sticky headers, horizontal overflow, row
stripes/hover/selection, disabled records, and loading/empty bodies. Sort requests
toggle one host key; select-all affects enabled records in the supplied view.
Native editors retain identity through row/column reordering. An explicit host
focus destination handles removal. No dependency was added.

Focused tests cover native keyboard actions, unchanged host data until requests
are applied, mixed selection, disabled rows, independent actions, stable editing,
focus return, table semantics, fractional geometry, oversized cells, sticky
scrolling, state replacement and narrow composition. Rendering review corrected
empty guidance that was clipped to off-screen column width; it now follows the
visible viewport even after horizontal scrolling. Theme/scale baselines and the
host filter/sort/select/paginate example are recorded in the
[verification record](../verification-tables.md).

This first implementation visits all supplied cells each pass; the host must
bound or paginate large datasets. It has no virtualization, resizing/pinning,
dragging, multicolumn sort, arbitrary spans or spreadsheet navigation. Loading
replaces stale records rather than overlaying active cells. Screen-reader and
broader platform acceptance remain explicit verification limits. The remaining
advanced image, file and drawing groups are still planned.
