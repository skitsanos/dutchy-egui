# DS-106 — Enforce compatibility with the published API in CI

Status: Resolved in 1.1.1 · 2026-11-10

## Problem

The first crates.io release, 1.1.0, establishes a public compatibility baseline.
The API extensibility guard checks type declarations but does not detect removed
methods or changed signatures, and CI does not yet compare the published API.

## Remediation

Install current stable cargo-semver-checks 0.51.0 in the Ubuntu quality job and
add the comparison to `scripts/check.sh`, with explicit
`--baseline-version 1.1.0 --all-features`. Keep the same command locally and in
CI, with normal failure propagation and no skipped comparisons. Update the
development and versioning guides. Verify an unchanged API passes and an
isolated breaking change fails, then run all qualification gates.

## Resolution

CI installs pinned 0.51.0 and invokes the shared gate against published 1.1.0,
with all features enabled for both versions. The baseline is explicit and
failures propagate normally; library dependencies and APIs are unchanged.

All 23 local gates pass, including 647 all-feature tests, 411 minimal tests,
three strict Clippy profiles, docs, WASM/MSRV, native builds and actual archive
inspection. Library snapshots are unchanged; the two Todo header baselines
were refreshed for the 1.1.1 version label. The real comparison passes 229 checks
(31 tool-skipped as inapplicable), while renaming the optional-feature
`UrlImageOptions::max_concurrent` method in an isolated copy produces the
expected deny-level failure, exit 100.
