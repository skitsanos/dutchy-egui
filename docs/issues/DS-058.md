# DS-058 — Anchor the distributable package allowlist at the repository root

Status: Resolved in 1.0.23 · 2026-11-08

## Problem

The 1.0.22 local package-content inspection found
`media/showcase-video/AGENTS.md` in the generated crate. An unanchored
`AGENTS.md` allowlist pattern matches at any depth; explicit Cargo includes
override gitignore. The shell command continued after the inspection failed,
so the already-qualified source was committed and pushed before this packaging
fix. No media file was staged, pushed or published to a registry. The generated
crate was removed during post-push cleanup.

## Remediation

Root-anchor every package include. Check both Cargo's file list and the actual
tar archive, including font licenses and new component sources. Compare archive
content with checkout files, allowing Cargo's generated manifest and minimized
lockfile. Keep release steps sequential so a failed content gate stops delivery.

## Resolution

Root anchors and snapshot-difference exclusions are implemented locally.
Cargo's file-list gate and the actual 538-file archive exclude media, target
outputs and generated snapshot differences. Checked 534 content files against
the checkout, the original/normalized manifest and bundled licenses. The crate
passed Cargo's isolated verification build. All 772 inventoried media/storyboard
files remain unchanged. AGENTS.md now requires package inspection before push
and separates delivery actions from qualification.

The original source release was 1.0.22 at
`0c60a874d257096438052013cd6de26b6d3b96e7`. This fix is included in repository
release 1.0.23, following the required version advance and package gate.

Reference: [Cargo include/exclude semantics](https://doc.rust-lang.org/cargo/reference/manifest.html#the-exclude-and-include-fields).
