# DS-094 — KeyRecorder drops Control from Command+Control chords on macOS

Status: Resolved in 1.0.28 (found in its review) · Priority: P3 · 2026-11-09

## Problem

The recorder folds platform modifiers into a portable chord by clearing
Control whenever Command is set. On Windows and Linux that is correct, because
Command is Control there. On macOS they are separate keys, so pressing
Command+Control+N stores and displays Command+N. The new binding then also
fires on plain Command+N, and a reserved Command+N reports a conflict for a
chord the user did not press.

A scratch probe with a macOS harness pressed Command+Control+N. The stored
value was `KeyboardShortcut { modifiers: command, logical_key: N }`.

## Remediation

Keep Control when the macOS Command key is held. Only fold Control into the
portable Command modifier where both name the same key. Add recorder
regressions for macOS and for a Control-platform harness, and confirm hint
formatting and conflict detection for the preserved chord.

## Resolution

Recorded chords keep Control with the macOS Command key; elsewhere Control
folds into portable Command. Dispatch and replay stripping now use the same
exact physical comparison as conflict detection. A Command binding therefore no
longer fires on Command+Control, and both chords can coexist on macOS.
Regressions cover recording on macOS and Windows, the "⌃⌘N" accessible
description and dispatch in both directions.
