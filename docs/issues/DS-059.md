# DS-059 — Add a native search field with independent clear and key hint

Status: Resolved locally · 2026-11-08

## Problem

Input supports native editing but has no reusable search composition. Applications
must recreate its magnifier, conditional clear target, decorative shortcut hint
and responsive spacing. Foliopress demonstrates the intended 48-point default
height and 16-point inset.

## Remediation

Add SearchInput over the shared native Input editor, with a SearchInput
accessibility role and named Clear button. Keep filtering and shortcut binding
in the host. Support all control sizes, char limits, disabled/read-only states,
focus return after clear and narrow layouts. Compose Kbd rather than drawing a
second chip implementation. Follow the combined implementation plan.

## Resolution

The public Widget composes the shared native Input editor and Kbd. Decorative
margin hit targets leave native text clicks unobstructed; Clear returns focus
and emits one host edit. Read-only controls suppress false edit notifications.
Five public interaction tests cover focus, Unicode limits, clear, disabled/
read-only state, stable IDs and narrow slots. Native macOS verified direct
pointer typing, clear, label/shortcut focus and controlled states.

The full suite passes with 435 all-feature and 324 no-default tests, formatting,
three Clippy configurations, rustdoc, WASM and native build. See
[verification evidence](../verification-media-card-search-input.md). No new
dependencies. Included in repository release 1.0.23.
