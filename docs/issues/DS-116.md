# DS-116 — DutchyMail sketch

Status: Sketch released in 1.4.1 · 2026-11-11

## Problem

The workbench components (TreeView, List, SplitPane, StatusBar and Avatar)
had only been shown one at a time in the showcase. The example-application
plan calls for a three-pane mail client to prove that they compose under
application-owned state and to surface the gaps they leave.

## Remediation

Sketch DutchyMail over a deterministic, fictional mailbox of 2,400 messages:
a folder TreeView with unread Badges, a virtualized message List with Avatar
rows, nested SplitPanes, a Markdown reading pane, a Toolbar, SearchInput, a
compose Modal, Toast undo and a StatusBar with a simulated sync. Build the
folder sidebar from TreeView inside a SplitPane instead of waiting for a
dedicated Sidebar component.

## Resolution

The sketch runs with `cargo run --example dutchy_mail --all-features`.
Selecting a folder lists its mail newest first; opening a message marks it
read until it is marked unread again. Archive, Delete and a discarded draft
each offer Undo. Search matches every word against sender and subject.

Composing it surfaced three host patterns. Single-letter shortcuts would
collide with List type-ahead, so compose, archive and search use Command
chords; Delete moves mail only when no text field has focus, because
egui's `wants_keyboard_input` is true for any focused widget. Nested
SplitPane closures cannot share a mutable model, so panes read the mailbox
and return intents that the frame applies afterwards; the reader shows the
selection from the start of the frame and a change repaints once more.

Twelve tests inside the example cover the mailbox, dates, folder switching,
read state, archive and Undo, Delete versus typing, search, sync, sending and
discarding drafts, plus light 1× and dark 2× baselines. Native macOS frames at
1× light and 2× dark rendered as expected; at the smaller 2× window the
toolbar wrapped and the StatusBar hid its lowest-priority hint.

Not in this step: MenuBar, context menus and the shared command registry,
fuzzy search, Skeleton loading, a discard confirmation (Undo replaces it),
folder renaming (TreeView rows are passive) and pane cycling with F6. No
screen reader session was run.
