# DS-110 — Host-owned SplitPane

Status: Resolved (unreleased) · 2026-11-10

## Problem

Workbench applications need resizable panes without hiding their layout state
inside the library. Pointer-only dividers and unconstrained child content can
make a split layout inaccessible or overflow its neighboring pane.

## Remediation

Add two-pane horizontal and vertical compositions with host-owned logical-point
sizes, minimum-size constraints, keyboard and assistive resizing, stable child
scopes and bounded clipping. Compose nested panes with TreeView and a document
preview in the showcase. Verify interaction, geometry and rendering across scales.

## Resolution

SplitPane now provides left/right and top/bottom compositions, proportional
minimum constraints, fixed outer geometry, stable child scopes and clipped
content. The host owns sizes and notebook drafts. Named Splitter semantics
include orientation, value/range and the controlled pane.

Native verification caught motion/release batching that click-and-drag detection
missed. Immediate drag sensing and a guarded complete-gesture path now handle
both cases once per frame, without taking gestures from panes or overlays.
The notebook source editor scrolls within its pane.

All 23 local gates passed: 712 all-feature and 469 minimal tests, strict Clippy
in three profiles, documentation, semver, WASM, MSRV, feature builds, examples
and actual archive inspection. Nineteen component tests and two notebook tests
cover input, clipping, state, nesting and rendering at light 1×, dark 1.5× and
blue 2×. Native macOS checks verified both mouse directions, both keyboard axes,
Tab order, size limits and long-source editing with the final caret reachable.
No VoiceOver session was performed.

See [the guide](../split-pane.md) for scope: no docking, Enter collapse/restore
or F6 pane cycling. No further release or push is part of this component work.
