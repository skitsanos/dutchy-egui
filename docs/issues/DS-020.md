# DS-020 — Center table content vertically

Status: Resolved · 2026-11-06

## Problem

Table cells started at the top of each row using their own natural heights.
Text, badges and header labels appeared above the center established by taller
checkboxes, action buttons or wrapped content. Expanding the semantic cell
rectangle alone did not center the actual controls.

## Remediation

Measure natural cell heights and place each content block at half the difference
from the tallest cell. Use stable cell keys and egui's layout-pass mechanism to
resolve new or changed measurements. Apply offsets before rendering so painting,
native hitboxes, focus and accessibility bounds stay together. Keep row height
independent of its centering offsets to avoid growth on repeated passes.

## Resolution

Header and body cells now share a vertical center. Comfortable and compact
padding remain symmetric. Wrapped cells determine row height; shorter text,
badges, selection controls and buttons are centered within it. Temporary keyed
measurements adapt to changed content, widths, density and column collections.
Host cell closures still run once per cell per egui pass.

Three regression tests assert actual child centers at 1x/1.5x/2x, wrapped-header
alignment, growth/shrink reflow, settled geometry, retained focus/identity, and
independent pointer/keyboard activation. Existing table interaction/overflow
checks remain in place. Updated theme/scale snapshots and native evidence are
recorded in [table verification](../verification-tables.md).

This corrects the initial top-aligned behavior described in DS-019's table step.
It adds no dependencies and does not change the host-owned data contract.
The nonvirtualized and platform limits in the table guide still apply.
