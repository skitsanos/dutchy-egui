# DS-062 — Add icon actions, toggle buttons and accessible toolbars

Status: Resolved in 1.0.24 · 2026-11-08

## Problem

Applications have text buttons and private icon/close painters but no public
icon-only or pressed-state button APIs. Building an editor/workbench toolbar
also requires repeated grouping, keyboard focus, overflow and action plumbing.

## Remediation

Implement IconButton, ToggleButton and typed Toolbar/ToolbarItem APIs with
application-owned state/actions. Supply original built-in vector icons and a
host painter option. Reuse tokens, variants, tooltips, focus and loading paint.
Give toolbars one remembered Tab stop, orientation-aware arrow/Home/End
navigation, disabled/busy skipping, stable IDs, focus repair and scrolling.
Document the contract and add showcase, interaction and rendering evidence.

## Resolution

Implemented the three APIs, 22 original icons/custom painters and three showcase
pages. Small toolbar rows use their own height; vertical bars explicitly compose
a column, reserve natural height and support bounded scrolling. Transparent
controls inherit inverse ink; disabled toggles retain pressed distinction.

At the original qualification, 452 all-feature and 335 minimal-feature tests
passed, along with fmt, the three
required Clippy configurations, strict rustdoc, WASM checks and native build.
Reviewed three new image baselines and native light/orange and dark/blue behavior;
existing baselines are unchanged. See the [guide](../actions-toolbars.md) and
[verification report](../verification-actions-toolbars.md) for evidence and limits.

The action components add no runtime dependency. The README was 42 lines at
that qualification; the later landing page is retained. The combined fixes and
Markdown support ship in [1.0.24](../verification-release-1.0.24.md).
