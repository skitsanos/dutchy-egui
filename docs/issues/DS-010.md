# DS-010 — Add controlled accordions and tabs

Status: Resolved · 2026-11-06

## Problem

The interaction-components milestone needs progressive disclosure and switchable
panels. Expansion/selection and content belong to the host; keyboard navigation,
disabled states, overflow, close requests, and focus after removal must compose
without importing widget/helper crates.

## Remediation

Add keyed accordion items with controlled single/multiple expansion, two surface
variants, named regions, and wrapping keyboard-accessible headers. Add keyed
underline/segmented tabs with manual activation, roving focus, active-panel
relationships, native horizontal scrolling, and independent close requests.
Verify state, identity, nested controls, focus, motion, themes/scales, and packaging.

## Resolution

Implemented on `ticket/accordions-tabs` (1.0.6), without new dependencies or copied
third-party widget code. AccordionState owns single/multiple expansion in the
host; headers retain native activation and support keyboard navigation. Both
surfaces wrap content and preserve body identities/spacing. Tabs provides two
surfaces, manual keyboard activation, roving focus, stable panels, disabled
items, horizontal overflow, close requests, and focus after host removal.

All 96 integration tests and one doctest pass, with 69 tests under no default
features. Required Clippy configurations, WASM compilation, rustdoc, packaging,
and the packaged-example check pass. Reviewed light/dark rendering at
1x/1.5x/2x, desktop/narrow layouts, and native macOS keyboard/child-action/close
workflows. Native review caught a nested-scroll baseline issue; a regression
test and corrected content-height calculation resolved it. All source files
remain below 400 lines. See the [guide](../accordions-tabs.md).

The host handles unsaved data and external panel-child focus restoration.
Overflow menus/arrows, arbitrary icons, docking/reordering, vertical tabs, and
panel-height animation are outside this step. Source-palette contrast remains
in DS-003; running screen-reader, Windows/Linux GUI, and minimum-toolchain
validation remain outstanding. Release 1.0.5 is on main as `954ca23`; this record
precedes the 1.0.6 release commit. The interaction-components milestone remains in progress.
