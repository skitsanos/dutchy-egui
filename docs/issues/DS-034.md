# DS-034 — Explicit spacing stacks on item spacing, and card details drift

Status: Resolved · 2026-11-07

## Problem

egui advances the cursor by `item_spacing` (8 points in the Dutchy style)
after every widget, so an explicit `ui.add_space(n)` that follows a widget
yields a gap of `8 + n`, not `n`. Several components add the web's documented
gap on top of that spacing:

| Place | Code gap | Rendered gap | Web |
| --- | --- | --- | --- |
| `Field` label to control (`src/widgets/forms/field.rs`) | 4 | 12 | 8 |
| `Progress` header to track (`src/widgets/progress/mod.rs`) | 8 | 16 | 8 |
| `Card::header` (`src/widgets/card/mod.rs`) | 16 | 24 | 16 |
| `Card::footer` above/below the divider | 24 / 16 | 32 / 24 | 24 / 16 |
| Skeleton card pattern (`src/widgets/skeleton/patterns.rs`) | 16 | 32 | 16 |

`docs/cards-alerts.md` says header/footer "add the documented spacing". The
rendered values are visible in `tests/snapshots/loading-light-1x.png` and
`surfaces-light-1x.png`.

Other card details not recorded as intentional: `Card::footer` calls
`ui.separator()`, which paints the 2-point `noninteractive.bg_stroke` set by
the theme, while the code comment and the web footer (`border-t`) are 1 point;
the separator keeps the border color on Dark/Primary fills. `Card::title`
reuses `Text::heading` and so applies −0.05 em tracking, while the live
`CardTitle` has none. Dark/Primary descriptions render at full inverse
opacity where the Markdown spec uses 70 %/80 % (the live component is always
muted-foreground). Finally, the scoped `override_text_color` that inverse
cards install also reaches native egui buttons and checkboxes, whose fills
stay `widgets.inactive` muted: a host `ui.button` inside a Primary card is
likely inverse text on a light fill. `Button` clears the override; native
controls do not. This last point is inferred from egui's text path, not
rendered.

## Remediation

Subtract `item_spacing.y` from explicit gaps (or set it to zero inside the
helpers) so the documented 8/16/24 values render as written, and add a
geometry assertion for one of them. Paint the footer divider as a 1-point
`border::THIN` line in the surface's divider color. Give `Card::title`
`Tracking::Normal`. Record the inverse-description opacity decision. Either
document that native interactive widgets inside inverse cards need host
styling, or scope the override to text by also adjusting
`widgets.inactive`/`hovered` fills in `card/style.rs`.

## Resolution

Fixed in 1.0.16. A crate-private `layout::gap_after` subtracts egui's item
spacing from an explicit gap, and `Field`, `Progress`, `Card::header`,
`Card::footer`, the skeleton card pattern and the empty-state actions use it,
so the documented 8/8/16/24/16/24 values render as written.
`tests/form_lifecycle.rs` asserts the 8-point label gap, `tests/cards.rs` the
16-point header gap and the 24 + 1 + 16 footer rhythm, and
`tests/empty_states.rs` the 24-point action gap. The footer divider is a
one-point `border::THIN` line in the border color, which the live
`CardFooter` (`border-t border-border`) also keeps on every surface.
`Card::title` uses `Tracking::Normal`. `docs/cards-alerts.md` records the
full-opacity inverse descriptions and that native egui controls inside inverse
cards keep their muted fills. The loading and surface baselines were refreshed.
