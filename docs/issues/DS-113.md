# DS-113 — Avatar with initials, image and presence

Status: Resolved (unreleased) · 2026-11-10

## Problem

Mail, chat and directory screens need a compact identity mark next to a
name. The library had no avatar, so hosts would paint their own squares,
derive initials inconsistently and convey presence by color alone.

## Remediation

Add a passive Avatar on the shared tokens: four square sizes, four fill
variants, initials from the first and last words of a display name, an
optional image from the existing loader pipeline with initials as the
fallback, and a presence marker described in words. Add a showcase, a guide
and tests for initials, geometry, image states, presence and composition in
clickable rows.

## Resolution

Avatar ships with 24/32/48/64-point sides, Muted, Default, Primary and Outline
fills, Unicode-aware initials with a host override, cover-cropped images that
are polled only while visible, a busy state while loading and initials when
loading fails. Presence paints a ringed square in the bottom-right corner and
becomes the accessible description. The avatar is an image named after the
person and leaves clicks to its container.

Rendering review found the presence marker covering the second initial on the
smallest size, so each size now has its own marker side (4, 8, 12 and 16
points) that keeps two initials clear.

Seven integration tests and three initials unit tests cover derivation, blank
names, sizes, presence geometry and description, ready, pending and failed
images, and pass-through clicks; a showcase test selects a directory row by
clicking its avatar. Baselines cover every variant, size and presence at
light 1×, dark 1.5× and blue 2×. No native window or screen reader was
exercised.

See [the guide](../avatar.md) for scope: no avatar groups, overflow counts or
name-derived colors.
