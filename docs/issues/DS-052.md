# DS-052 — Extreme typed values overflow intermediate arithmetic

Status: Resolved in 1.0.20 · 2026-11-07

## Problem

Epoch conversion and adding extreme day offsets could overflow before returning
`None`. Large time segment deltas overflowed an `i32` addition. Typing the valid
finite `f64::MAX` with decimal rounding enabled produced infinity.

## Remediation

Reject unsupported epoch days before civil conversion, use checked day addition,
and widen time-step intermediates to `i64` before wrapping. Round a numeric
value only when its scaled intermediate is finite; otherwise retain the finite
input before applying the configured range.

## Resolution

`tests/calendar_limits.rs` covers extreme `i64` epoch/day offsets and `i32`
time steps. `tests/numeric_limits.rs` types `f64::MAX` through the editor and
verifies that it stays finite and unchanged. Each case reproduced the failure
before remediation. Normal parsing, stepping and bounds tests also pass.
