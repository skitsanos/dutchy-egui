# DS-103 — DutchyAgent review: layout, focus, state and transport faults

Status: Resolved in 1.0.30 (found in its review) · Priority: P2 · 2026-11-09

## Problem

An independent review of the then-unreleased DutchyAgent (DS-099..101) passed every
gate but found nine faults that the tests did not catch:

1. The heading subtitle sits about 14 points below the "Delete conversation"
   label in every baseline. The cause is in the library; see DS-104.
2. The empty-state "Try the Rust example" action replaces a draft the user has
   typed into an empty conversation, then sends the sample.
3. Once the settings icon has been clicked, opening settings with Cmd+, and
   closing it returns focus to that icon instead of the message field.
4. Sidebar rows show "· replying" and a selected fill, but their accessible
   names carry neither state.
5. A failed or stopped reply with no text adds an empty text row, leaving a
   gap above the error.
6. At narrow widths the running hint starts beside the actions and continues
   on the next row at the left edge.
7. The 90-second timeout is ureq's total budget for the response body, not an
   idle limit. A reply streaming longer fails as "Could not reach OpenAI",
   which blames the network. Nothing limits the wait before headers, so a
   buffered request can wait indefinitely.
8. `max_output_tokens: 2048` includes reasoning tokens, so High effort can use
   the budget before writing text. Streaming and buffered paths also report an
   early stop with different messages, neither naming the cause.
9. The crate comment in `main.rs` still calls the application offline.

## Remediation

Keep the user's draft when sending the sample. Restore focus to the widget
that was focused when the shortcut opened settings. Mark sidebar rows as
selected and describe a running reply. Add reply text only when there is
some. Move the hint to its own row when it does not fit beside the actions.

Replace the body budget with a provider watchdog that measures time since
OpenAI last sent anything, in both modes, and keep a long body budget only to
end abandoned reader threads. Report connection failures, interruptions and
the watchdog separately. Scale the output limit with effort and report an
incomplete reply by its stated reason in both paths. Correct the comment.

Each behavior gets a test that fails before the fix: kittest interaction and
accessibility checks for the UI, and loopback HTTP for the transport. No live
OpenAI requests are made.

## Resolution

All nine are fixed. Eleven new tests failed before their fix and pass after
it. The six kittest checks cover the sample draft, Cmd+, focus return, sidebar
selected and running states, the empty error row, heading and composer
centering, and a hint kept whole at 480, 560 and 1160 points. The five loopback
and decoder checks cover silence measured against a reply longer than the
limit, a buffered request with no headers, unreachable versus interrupted
wording, effort-scaled limits, and incomplete replies keeping text. The
watchdog tests drive frame time directly, so none of them waits minutes.

Nine Agent baselines changed as intended. `scripts/check.sh` passes: 642
all-feature and 407 minimal tests, three strict Clippy profiles, docs, WASM,
MSRV, examples and the package allowlist. Native Glow captures at 1x light and
2x dark, in offline mock with no `.env` loaded, confirm the alignment. No live
OpenAI request was made, so real streaming, the High-effort limit and the
watchdog against OpenAI remain unverified. Deleting a conversation still has no
confirmation or undo.
