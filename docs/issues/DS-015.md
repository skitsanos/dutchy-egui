# DS-015 — Implement controlled workflow progress

Status: Resolved for this step · 2026-11-06

## Problem

The interaction milestone lacked a stepper. Applications needed clear workflow
position and completion, narrow-layout behavior, accessible status, and optional
navigation without moving field values, validation, or submission into the library.
The web position formula also required explicit empty/single-step handling.

## Remediation

Implement keyed host-owned state with not-started, current, and complete states;
horizontal, vertical, compact, and position-progress variants; shared geometry
and palette/type tokens; native optional navigation requests; stable identity;
wrapped labels/descriptions and compact scrolling. Demonstrate validation and
focus placement through the existing public form API.

## Resolution

Version 1.0.9 adds `Step`, `StepperState`, `Stepper`, and result/variant types.
Indicators are read-only unless explicitly navigable. Native pointer/Enter/Space
activation returns a key for the host to accept or reject. The current step is
named semantically, status/position/descriptions remain accessible, and native
focus survives renaming, sibling insertion, and presentation changes.

Horizontal layouts adapt vertically; compact focus reveals overflow. Empty,
single, unknown-current, and complete states have finite explicit percentages.
Progress measures position: 100% at the final current step does not submit work
or imply completion. The host marks completion separately.

The showcase retains input across Back/revisit, gates advancement with existing
validation, and places focus after transitions. Interaction tests cover native
activation, disabled/read-only behavior, identity, bounds, state boundaries,
focus, repeated-frame geometry, and fractional-width column alignment. Native
review caught and corrected a wrapped final marker and diagonal connector.
Theme/scale snapshots and native evidence
are recorded in the [verification record](../verification-stepper.md).

No dependencies were added. The model is linear; branching, skipped/failed steps,
async execution, and navigation policies remain host concerns. Platform and
screen-reader acceptance limits remain explicit in the verification record.
