# DS-097 — CI snapshot comparisons fail under Linux software Vulkan

Status: Resolved in 1.0.28 (found in its review) · Priority: P2 · 2026-11-09

## Problem

The new workflow runs every snapshot test on Ubuntu with software Vulkan, but
the baselines are rendered on macOS Metal and compared with kittest's default
tolerance. A local rehearsal of the workflow's test step failed: Ubuntu 24.04,
the workflow's packages and environment, stable Rust 1.99.1, run in Docker on
arm64 rather than the hosted x86_64 runner.

587 tests passed and three failed. `rich-menus-light-1x-checks` differed in
2 pixels, and the older `images-light-1x` and `image-expand-hover` baselines
in 234 pixels each. The differences are single-column edge rasterization at
block boundaries, invisible at normal size. The first hosted run would likely
fail the quality job for the same reason.

## Remediation

Make pixel comparisons renderer-tolerant, for example with a small
`failed_pixel_count_threshold` for the affected snapshots, or keep pixel
baselines on macOS and run Linux rendering as a smoke check. Avoid
regenerating baselines from Linux output alone. Confirm on the hosted runner,
which may differ from the arm64 rehearsal.

## Resolution

A root `kittest.toml` keeps macOS comparisons strict and allows up to 512
differing pixels per snapshot on Linux only, about twice the measured worst
case. It ships in the crate, so packaged tests behave the same, and the
archive inspector approves it. The development guide records that baselines
are refreshed on macOS only. A rerun of the arm64 rehearsal on the fixed tree
passed 596 tests with no failures. The hosted x86_64 run on the 1.0.28 push
passed.
