# DS-102 — The crate package exceeds the crates.io upload limit

Status: Resolved (unreleased) · Priority: P2 · 2026-11-09

## Problem

A `cargo publish --dry-run` of 1.0.29 packaged 733 files, 21.8 MiB and
11.5 MiB compressed. crates.io rejects archives over 10 MB, so the crate could
not be published. The 131 image baselines in `tests/snapshots` (17.4 MB) caused
most of the size. Tests and examples only help in a repository checkout:
dependents never build or run them, and docs.rs documents the library from
rustdoc.

## Remediation

Keep tests, image baselines and examples in the repository, where developers
can take the examples from GitHub. Package only the library, the bundled fonts
with their licence notices, the docs and the root notices. Make the archive
inspector reject packaged `tests/` or `examples/` paths and archives over the
upload limit.

## Resolution

The root-anchored include list no longer names `/tests/**`, `/examples/**` or
`kittest.toml`. Cargo removes the unpackaged test and example targets from the
published manifest (`autotests` and `autoexamples` false) and warns once for
each, which is expected. The archive is now 418 files, 4.1 MiB and 1.7 MiB
compressed, under a fifth of the limit. `scripts/check_package.py` asserts the
limit and the exclusions. `scripts/check.sh` passes with 1,061 tests;
repository tests, rendering baselines and examples are unchanged. Not yet
released or published.
