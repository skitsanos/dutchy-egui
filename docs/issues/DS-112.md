# DS-112 — Host-owned StatusBar

Status: Resolved in 1.4.0 · 2026-11-10

## Problem

Workbench applications such as the planned DutchyMail need a bottom strip of
counts, sync state, progress and shortcut hints. The examples hand-build one
in `examples/support`, which drops hints from the end, offers no clickable or
progress segments and exposes no status semantics.

## Remediation

Add a StatusBar of keyed, host-formatted segments: text, label/value and Kbd
hints with optional icons, tone markers and inline progress, packed at the
start or end. Hide segments by priority when space runs out and report them,
elide a lone segment that still cannot fit, make chosen segments clickable,
and expose a named group with label, button, progress and live status roles.
Add a showcase, a guide and interaction, semantics and rendering tests.

## Resolution

StatusBar ships with priority overflow (lowest first, later items first on
ties), hidden-key reporting, ellipsis with a full-text tooltip, clickable
segments activated by pointer, Enter, Space and assistive Click, per-segment
and whole-bar disabling, keyed focus across reordering and opt-in polite live
segments. The **Status bars** showcase simulates a mailbox sync, a failed sync
and a width control.

Building it showed that a Label with separate label and value is read by its
value alone, because AccessKit derives a label's text from its value. Passive
segments therefore speak their whole text ("Unread: 42"), while buttons and
progress indicators keep label and value apart.

Eleven integration tests and three layout unit tests cover geometry, overflow,
elision, unbounded and zero widths, activation, focus order, disabling,
reordering, roles and live/progress metadata. Three showcase tests run the
simulated sync, the failure state and a narrow bar. Baselines show rest at
light 1×, hover at dark 1.5× and focus at blue 2×. No native window or screen
reader was exercised.

The examples' own status strip stays until DutchyMail adopts the component.
See [the guide](../status-bar.md) for scope: no overflow menu, resizing or
multi-line segments.
