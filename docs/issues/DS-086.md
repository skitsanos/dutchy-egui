# DS-086 — Todo imported IDs overflow counters and strand file jobs

Status: Resolved in 1.0.27 · Priority: P2 · 2026-11-09

## Problem

Import accepts `u64::MAX` project/task IDs, then overflows when computing the
next identifier. Near-maximum IDs also make later creation overflow. In debug
builds the file worker panics; a disconnected channel is treated as still
pending, leaving Import/Export disabled. Optimized arithmetic can wrap and reuse
existing IDs.

## Remediation

Use checked, monotonic ID allocation and reservation. Reject unrepresentable
record IDs as line-numbered import errors; report exhausted creation without
changing existing records or losing drafts. Convert failed/disconnected file
workers into completed error outcomes, request repaint and permit later jobs.
Cover boundaries in both debug and optimized builds and verify the native
import error/recovery flow.

## Resolution

Checked counters reject maximum IDs and leave records unchanged on exhaustion.
Creation preserves drafts; task-save errors render inside the open drawer.
Disconnected and panicking workers produce errors, release busy state and
allow later jobs. Debug regressions and an optimized production-source boundary
probe pass with overflow checks disabled. Native macOS imports report Line 2
for maximum project IDs and Line 3 for maximum task IDs; the original store
survives, and a subsequent valid import succeeds. The full 14-gate matrix
passes. No dependency change. Included in release 1.0.27.
