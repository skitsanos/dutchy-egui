# DS-045 — Showcase sidebar hides arriving keyboard focus

Status: Resolved in 1.0.18 · 2026-11-07

## Problem

The 1.0.17 sidebar correctly scrolls its page list above a pinned footer, but
does not reveal a button when keyboard or assistive focus arrives. In the
native macOS showcase at 1200 × 940 points, Shift+Tab from the Lightboxes
page reached the sidebar's Tooltips button while the list still showed only
Overview through File uploads. Focus existed outside the visible page list.
The existing sidebar test explicitly called `scroll_to_me`, hiding this gap.

## Remediation

Reveal a clipped sidebar button and its entire focus outline on `gained_focus()`
only, using immediate scrolling and token-sized edge space. Retained focus
must not override subsequent wheel input, following
the DS-026/DS-038 rule. Keep the pinned footer and the inline narrow navigation.

## Resolution

The showcase navigation now requests a reveal only for arriving focus on a
clipped full-width sidebar button or its outline. The regression in `tests/rendering.rs`
failed before the fix: Tooltips ended at y=1446 below the footer at y=488 in
the 600-point viewport. It checks reveal at 600- and 940-point viewport heights,
asserts the entire painted outline fits inside its clip, then wheels away
with focus retained and asserts that the list stays scrolled and the footer
stays fixed. Native follow-up exposed the initially clipped bottom edge;
token-sized scroll-content insets now leave room for the full outline.
See `docs/verification-review-1.0.17.md` for the
completed check matrix and native follow-up. This is a local follow-up to
1.0.17; no new release or push is implied.

Independent check on 2026-11-07: with the sidebar restored to `9d841db` the
regression failed as described (Tooltips at y 1414–1446 against the footer at
y 488 in the 600-point viewport); with the fix it passed with the rest of
`tests/rendering.rs`. Formatting, the three Clippy configurations, rustdoc,
both wasm checks and both suites (348 tests with all features, 250 without
defaults) pass. A window resize with retained focus does not re-reveal a
clipped button; the remediation limits reveal to focus arrival. The native
Shift+Tab path was not repeated. The changelog carries this entry under
"Unreleased"; pushing it requires the 1.0.18 bump.
