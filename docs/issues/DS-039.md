# DS-039 — File selection and Scribble: geometry drift, a size-format defect, and unrecorded decisions

Status: Resolved for the defects · 2026-11-07

## Problem

File selection (`src/widgets/upload`, `src/tokens/upload.rs`) against the
live `FileUpload` component and `components/file-upload.md`:

- Zone padding is 24 points (live `p-8` = 32, spec `p-12` = 48); the upload
  glyph is 20 (live 24, spec 40); the 192-point minimum height has no web
  counterpart. The instruction uses `Text::label` (mono, 0.1 em, uppercase)
  where the web uses the bold body face at 14 points with 0.05 em. The compact
  control is 56 points high and full width; the spec's styled input is an
  inline 48-point control with a plus glyph. Hover/drag fill follows the spec
  (5 % primary) while the live component uses 30 % muted.
- `file_size` (`src/widgets/upload/policy.rs`) chooses the unit before
  rounding, so values from 999,950 to 999,999 bytes print "1000.0 KB"
  instead of "1.0 MB" (same at every unit boundary). Decimal units are
  documented, but the live script uses binary multiples labelled "MB".
- Row captions use `Text::label` ("SIZE UNKNOWN") where the spec is regular
  mono; the row progress track is 4 points (spec 8); the close glyph is 12
  points in a 32-point target (spec 16 in 24).
- `focus::restore` treats "origin not among enabled controls" as removal, so
  disabling a row after Cancel moves focus to the next control although the
  row remains.
- `docs/01-design-system/tokens/effects.md` states that the system has no
  dashed borders, while the file-upload spec, the live component, and the port
  all draw a dashed 2-point zone. The port's guides never record the conflict.

Scribble (`src/widgets/scribble`, `src/scribble`, `src/tokens/scribble.rs`):

- Paper is the warm light background (#FAF8F5) in every theme; the live
  canvas wrapper is `bg-white`. `docs/scribble-export.md` records the fixed
  paper/ink tokens but not that white was replaced.
- Ctrl/Cmd+Z or Y during an active keyboard draft cancels the draft and emits
  no history request (`keyboard.rs`), while Delete cancels and requests Clear.
  The guide says a draft is cancelled before a history request, implying both.
- Hitting the per-gesture point cap discards the whole in-progress stroke
  (`capture.rs`) instead of committing what was captured; only the stroke cap
  is tested.

Drop claiming, limits, export arithmetic, SVG content, undo/redo bounds, and
accessibility names were verified clean; the `expect`/`unwrap` sites cannot
fail under the token constants and capture invariants.

## Remediation

Fix `file_size` by rounding before choosing the unit. Align or record the
zone/row geometry and typography, the hover fill source, and the paper color.
Document the dashed-border exception in `docs/reference.md`. Either emit
Undo/Redo after cancelling a keyboard draft or correct the guide. Commit the
captured points when the gesture cap is reached. Note the focus-return
heuristic in the guide.

## Resolution

Resolved for the defects on 2026-11-07 (1.0.16). `file_size` rounds before
choosing the unit; `tests/file_rules.rs` covers 999,949 ("999.9 KB"), 999,950
("1.0 MB") and the gigabyte boundary. A gesture that reaches the per-stroke
point cap commits the captured points and reports `Capacity("gesture points")`
(`tests/scribble_capacity.rs`); the same file characterizes Undo/Redo during a
keyboard draft (the draft is cancelled, the next press reaches history), which
`docs/scribble-export.md` now states together with the white-to-paper
replacement. The drop zone follows the live component: 32-point padding, a
24-point glyph, the bold 14-point uppercase body instruction, a muted 30 %
hover/drag fill and 50 % press; rows use medium-weight names, plain mono
sizes, 8-point tracks and 16-point dismiss glyphs. The file-upload and
remove-hover baselines were refreshed. `docs/reference.md` records the
dashed-border exception; `docs/file-uploads.md` records the hover source, the
live-aligned geometry and the focus-return rule for rows disabled after Cancel.

Recorded differences that remain: the compact control (a full-width 56-point
surface where the web uses an inline 48-point input), the 192-point minimum
zone height, and binary-multiple sizes labelled "MB" in the live script.
