# DS-122 — Filter chip groups

Status: Resolved (unreleased) · 2026-11-11

## Problem

Applications composing filters from individual chips need to repeat keyed
layout, accessibility grouping, and request handling for each filter row.

## Remediation

Build a wrapping, named FilterChipGroup from toggleable Chips. Read selection
from the host and return keyed requests for the host to accept or decline.
Demonstrate independent filter groups in Showcase.

## Resolution

FilterChipGroup exposes stable keys, typed activation requests and disabled
choices. It wraps existing Chips in a named region with native Tab order. The
host supplies selection and decides which requests to apply. Showcase combines
multiple media types with one collection and displays matching assets.

Review found two layout faults. The first row started as tall as the remaining
space and absorbed later rows, so a chip after a wrapped one returned to the
top row, out of Tab order. Gaps also followed the parent's spacing. The group
now starts with one chip-high row and spaces chips with the small token.

Tests cover ignored requests, disabled transitions, focus across reorder and
renaming, reading order in wrapped rows from either edge, token gaps under
custom parent spacing, and selected and idle fills in narrow light 1× and
dark 2× layouts. Both layout tests fail without their fixes.
Native macOS checks covered pointer and keyboard filtering, disabled Tab
skipping, empty results and changing themes with filters selected.
