# DS-027 — Status and accent text on neutral surfaces also falls below AA

Status: Resolved · 2026-11-07

## Problem

DS-003 records white labels on the orange, warning, success, and destructive
fills. The same source colors are also used as text on neutral surfaces, and
those pairs were never recorded. Relative-luminance ratios from the exact token
bytes in `src/tokens/color.rs`, without alpha compositing:

| Text on background | Light mode | Dark mode |
| --- | --- | --- |
| Orange accent | 2.63:1 | 7.11:1 |
| Purple accent | 4.99:1 | 3.74:1 |
| Crimson accent | 4.27:1 | 4.38:1 |
| Destructive | 3.57:1 | 5.24:1 |
| Success | 3.15:1 | 5.94:1 |
| Warning | 2.01:1 | 9.28:1 |
| Info | 4.40:1 | 4.24:1 |

Normal text needs 4.5:1. The library renders two of these pairs itself: the
12-point field error message in `Field` (`src/widgets/forms/field.rs`) and the
file-row error message in `FileList` (`src/widgets/upload/rows.rs`) both use
`TextColor::Destructive` on the surface background. The theme also sets egui's
hyperlink color to the accent, so native links on Orange/light are 2.63:1.
`TextColor::Primary` and `TextColor::Success` are public, and the showcase uses
accent-colored labels. The web source has the same treatment
(`.dutchy-field-error [data-field-error]` is hsl(0 84% 60%) at 0.75rem), so the
limitation is inherited rather than introduced. Muted text passes everywhere
(5.40:1 on background, 5.08:1 on muted, 4.81:1 on secondary in light mode).

## Remediation

Follow the DS-003 policy: preserve the source appearance and make no blanket
contrast claim. A later design decision can add darker light-mode text tokens
for destructive/success/warning/info, or keep the existing non-color cues as
the primary signal (fields already pair the message with a 2-point destructive
border; file rows pair it with a Retry control). Mention this entry beside
DS-003 in the README when the decision is made.

## Resolution

Closed as a design decision on 2026-11-07: the library keeps the design
system's colors for status and accent text, including the pairs above that fall
below 4.5:1. The computed styles of the localhost reference
(`http://localhost:4545/`) match the port's palette byte for byte (measured
during DS-028), so the shortfall is inherited rather than introduced. Large
text (24-point regular or about 19-point bold, threshold 3:1) passes for
destructive and success on the light background; the 12-point error messages
do not qualify, so their non-color cues stay in place (the 2-point destructive
field border, the file-row Retry control, the live alert and invalid metadata).

Applications that need stricter ratios tune them on their side. `Palette`
fields are public: a host darkens `destructive`, `success`, `warning`, `info`
or `primary` on its `Theme` before `dutchy_egui::install`, which also moves the
field and file-row error messages and the hyperlink color. The same token
colors the matching fill, so a host that wants darker text without a darker
fill uses `TextColor::Custom` on the text it renders. No darker light-mode text
tokens are added and no blanket contrast claim is made; the README and the
reference contract mention this entry beside DS-003.
