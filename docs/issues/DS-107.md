# DS-107 — Keyed List and fixed-height virtualization

Status: Resolved in 1.2.0 · 2026-11-10

## Problem

Workbench applications need reusable row selection, focus and scrolling.
Separate hand-written lists duplicate keyboard and accessibility behavior;
the planned VirtualList would split those behaviors from their row engine.

## Remediation

Add List with host-owned keyed rows/state, none/single/multiple selection,
modifier ranges, type-ahead, one roving Tab stop, list box metadata and egui
row-range virtualization. Preserve offscreen focus during manual scrolling,
expose activation requests, compose passive content, and demonstrate 10,000
rows. Document scope and run interaction, rendering and full qualification
checks without new runtime dependencies.

## Resolution

List now supplies the shared keyed, fixed-height collection. Selection, focus,
range anchors and the bounded typed prefix live in host-owned state. Pointer
edits resolve before row painting and accessibility metadata, keeping single
selection consistent in the click frame. A focus proxy preserves manually
scrolled-away rows; native scroll-into-view actions do not steal focus.

A review before release found five gaps, now fixed with tests: type-ahead
stopped at a space while Space toggled the focused row; a per-frame copy of
the selection made frame time grow with it; long default labels were clipped
mid-glyph instead of elided; the empty text was fixed; and a bare macOS
Control-click toggled selection. Edits now report changes directly, so a debug
frame with 100,000 selected rows fell from 143 to 121 ms.

All 23 local gates pass: 671 all-feature and 434 minimal tests, strict Clippy,
SemVer against published 1.1.0, docs, WASM/MSRV and archive inspection.
Twenty-four List tests cover interaction and three rendering baselines at 1×,
1.5× and 2×; existing baselines are unchanged. Before the review, native macOS
checks proved ranges, End/Enter, type-ahead, one-stop Tab exit and Select All
of 9,412 enabled rows in the 10,000-row showcase.

No runtime dependencies were added. Fixed heights, passive row content,
linear metadata validation and visible/focused accessibility nodes are the
supported scope; see [List](../lists.md).
