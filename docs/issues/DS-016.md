# DS-016 — Implement blocking dialogs and side drawers

Status: Resolved for this step · 2026-11-06

## Problem

Applications lacked general Dutchy modals and drawers. They needed sharp,
accessible overlays that block the workspace, constrain long content, dismiss
predictably, and return focus without taking ownership of fields or business work.
A docked egui SidePanel alone would not provide these guarantees.

## Remediation

Use native `egui::Modal` for both surfaces, with shared token widths, header/body/
footer geometry, a named title, and the existing close-control feedback. Add
left/right full-height drawers, reduced-motion-aware entrances, configurable
Escape/backdrop/close behavior, host visibility, and deferred focus restoration.
Demonstrate confirmation, validated editing, and retained drawer preferences.

## Resolution

Version 1.0.10 adds `Modal`, `Drawer`, width/side options, common focus/dismissal
options, and typed closure/dismissal results. Native modality blocks underlying
input and preserves Tab behavior. Escape closes child popups first. Host-driven
closure follows the same focus lifecycle; a surviving return target may replace
a removed opener. Header controls stay reachable while content and footer scroll.

Tests cover activation, read-only/locked dismissal policy, input blocking, native
focus confinement, initial/return/replacement focus, stacked topmost dismissal,
stable fields, narrow bounds, long-content footer reachability, and entrance/
reduced-motion scheduling. Rendering review corrected a shrinking title column
that misplaced Close. Other regressions corrected initial full-height allocation
and replacement-target updates. Keyboard focus now reveals off-screen content
controls, including long-content footer actions. Theme/scale baselines and macOS native host flows
are recorded in the [verification record](../verification-overlays.md).

No dependencies were added; current egui-family versions were verified. Values,
validation, saving, and draft reset remain host-owned. Call overlays every frame,
including closed frames, so deferred focus restoration completes. Footers scroll
with content; closing is immediate. Docked/resizable/top/bottom drawers, exit
animation, and broader platform/screen-reader acceptance remain outside this step.
