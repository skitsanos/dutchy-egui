# DS-056 — Add color editing and prioritize native Rust components

Status: Resolved in 1.0.22 · 2026-11-07

## Problem

Applications cannot compose a public Dutchy color picker. The web registry is
also too narrow to guide a Rust library intended for developer tools and rich
native applications. Existing component groups have partial variants, while
useful additions such as icon actions, multi-select and workbench layouts are
not prioritized.

## Remediation

Add `ColorPicker` and named `ColorPreset` data over an application-owned
`Color32`. Compose flat palette buttons, hex input, RGB/optional alpha sliders
and stepped numbers in a constrained popup. Use shared geometry, square
transparency previews and native interaction/accessibility; preserve hidden
straight RGB at zero alpha as temporary editing state. Support invalid drafts,
read-only inspection/copy, disabled parents and external host updates.

Add a dedicated showcase and tests for keyboard/focus, parsing, bounds,
transparency, host state and rendering. Document the editing contract and
record the broader product direction in AGENTS.md and the implementation plan.

## Resolution

Implementation is split between public widget, editor, painting, temporary
state and shared tokens. No dependency is added. All required checks passed:
421 tests with all features, 314 without defaults, formatting and the three
Clippy configurations with warnings denied. Rustdoc, both WASM configurations
and the native showcase build also passed.

Rendering review fixed swatch centering and initial popup height; keyboard
review fixed Escape focus restoration. Native macOS verified palette/hex,
transparent editing, disabled/read-only controls and focus return. Three new
theme/scale baselines were reviewed; existing baselines are unchanged. See
[verification evidence and platform limits](../verification-color-picker.md).
Included in repository release 1.0.22 after repeated release qualification.

The new [component roadmap](../component-roadmap.md) recommends icon actions
and toolbars, richer filtering, then tree/virtualized/split-pane foundations.
It also records developer-oriented inspectors, code/log views and compact
charts, plus the valuable extensions to existing widgets. The web site is a
visual reference rather than a limit on native components.
