# DS-040 — Media: spaced gallery gaps, caption tracking, and loader robustness

Status: Resolved for the defects · 2026-11-07

## Problem

- `Gallery` (`src/widgets/media/gallery.rs`) always wraps its grid in a frame
  filled with `palette.border`, whatever `gap` or `bordered` is set. That
  matches the web joined gallery (`gap-0.5 bg-border`), but the web's spaced
  grids have no border fill, so the showcase "Spaced tiles" example renders
  24-point bands between tiles in the border color.
  `docs/images-galleries-lightboxes.md` documents only the joined default.
- Caption source text uses `Tracking::Wide` (0.025 em,
  `src/widgets/media/caption.rs`); the spec and live component use
  `tracking-wider` (0.05 em). The guide says "wide tracking".
- `src/image_loaders/fetch.rs` decodes on the ehttp worker with no panic
  guard. If the codec panics on malformed input the thread unwinds, the
  permit is released, and the request's result stays empty, so the image
  reports Pending forever with no failure or retry affordance (on wasm a panic
  aborts). Whether `image` 0.25.10 can panic on crafted PNG/JPEG input was not
  determined.
- Smaller: the expand control uses one 80 % opacity where the web gallery
  uses 70 %; the figure and image nodes carry the same alternative text, so
  assistive technology may announce it twice; the cache uses the current
  viewport's pass counter for a context-wide cache, which can mis-evict in
  multi-viewport applications; `.height()` keeps `Contain` where the web
  `height` prop crops; lightbox backdrop dismissal covers only the 24-point
  gutter while the web closes on any click outside the image (the port's
  behavior is documented, the difference is not).

The `unwrap` sites in `fetch.rs`, `cache.rs`, and `caption.rs` were traced and
cannot fail under the surrounding control flow; redirects, signature sniffing,
byte/pixel/dimension bounds, eviction protection, forgotten callbacks, and the
straight-to-premultiplied conversion were verified.

## Remediation

Fill the gallery frame only when `bordered` or when the gap is the joined
micro gap, and document the joined/spaced treatments. Use `Tracking::Wider`
for source text. Wrap the decode in `catch_unwind` (or decode on the UI side
after a size preflight) and record a failure so retry remains available.
Record or align the minor items; consider dropping the duplicate alternative
text on the figure node.

## Resolution

Fixed in 1.0.16. Spaced galleries (any gap above the micro gap) no longer sit
on a border-colored frame: the fill and outer margin apply only to joined
galleries, and `bordered` borders each spaced tile instead;
`tests/media_rendering.rs` samples the pixel between two spaced tiles against
the page and keeps the joined hairline. Source credits use `Tracking::Wider`
(`tests/images.rs` reads the painted letter spacing). Gallery expand controls
use the new `GALLERY_EXPAND_OPACITY` token (70 %) while standalone images keep
80 % (`tests/galleries.rs`, `tests/images.rs`). `decode` runs inside
`catch_unwind` and reports a codec panic as "Image decoder failed" so retry
stays available (unit tests in `src/image_loaders/decode.rs`; wasm still
aborts on panic). The image, lightbox and expand-hover baselines were
refreshed. The shared figure name, the viewport pass counter, `.height()`
fitting and the backdrop gutter are recorded as decisions in
`docs/images-galleries-lightboxes.md` and `docs/url-images.md`.
