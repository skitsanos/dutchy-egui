# DS-070 — Coordinate the parallel Markdown/CodeBlock branch before integration

Status: Resolved in 1.0.24 · Priority: P3 · 2026-11-08

## Problem

Remote branch `gedankrayze/vibrant-cerf-rat7ho` contains commit `684a840`
(Markdown rendering and CodeBlock), based on 1.0.22 (`0c60a87`). It has diverged
from main's 1.0.23 (`cd2688f`) and is not part of the current local work through
DS-066. There is no open PR for it at review time. It is unmerged work, not a
cleanup candidate.

The branch also calls its version 1.0.23, assigns Markdown to DS-058 (already
used on main for the package allowlist fix), and retains the older unanchored
package include patterns. It enables a new default `markdown` feature with an
optional pulldown-cmark dependency. Blind integration could discard the current
package safeguards, collide in the ledger, or make dependency/docs claims stale.

## Remediation

Choose whether Markdown/CodeBlock belongs in the upcoming release or a later
one. If included, integrate onto the current main/local feature set, reconcile
the ticket numbers and guide links, retain root-anchored package exclusions,
reconcile showcase navigation and README, and qualify the combined feature,
dependency and package matrix under a version newer than 1.0.23.

## Resolution

The user selected Markdown for the next release. Commit `684a840` was ported
onto the current local work without replacing main's package exclusions,
DS-058, action components or per-page showcase scroll state. Its feature ticket
is now [DS-071](DS-071.md). The new parser is default-enabled but optional;
CodeBlock remains unconditional, and the fonts-only showcase still builds.

The combined feature matrix, native showcase and actual crate archive pass;
see [integration verification](../verification-fixes-markdown.md). Release
1.0.24 records the original branch commit as a parent while retaining the
qualified combined content. Its source history remains reachable from main;
the remote topic branch is eligible for post-push cleanup once ancestry and
remote equality are confirmed. See the
[release qualification](../verification-release-1.0.24.md).
