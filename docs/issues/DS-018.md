# DS-018 — Implement nonblocking toast notifications

Status: Resolved for this step · 2026-11-06

## Problem

The interaction milestone lacked toast notifications. Applications needed
severity feedback, stacking, expiry, dismissal and actions without blocking the
workspace, losing unread messages, or moving business work into the library.
The web's solid runtime and outlined documentation also needed an explicit mapping.

## Remediation

Implement an application-owned FIFO queue, stable IDs, typed single-use actions,
manual/expiry events, four corners and severity treatments, native controls, live
metadata, constrained overflow, and focus return. Pause visible lifetimes during
interaction, clipping, inactivity, modality, or explicit host policy. Keep waiting
entries unexpired and respect reduced motion.

## Resolution

Version 1.0.11 adds `Toast`, `ToastQueue<T>`, `Toasts`, and response/event/presentation
types. The host owns queue capacity/content and handles business actions. Three
entries render by default (configurable 1–4); pending entries retain their full
lifetime. Persistent notifications, replacement/removal, shared close feedback,
and a host Undo/Retry showcase complete the core interaction scope.

Two unit tests and seventeen integration tests cover clock boundaries, payload
consumption, visibility/queue timing, hover/focus/inactive/modal pause, scheduling,
identity, accessibility, nonblocking input, action/dismiss behavior, focus return,
narrow scrolling, corners, themes/scales, and host flows. Rendering review fixed
a doubled viewport inset. Metadata moved to the actual toast parent so controls
remain accessible children. Native expiry, keyboard dismissal, queue advancement,
and command-palette suspension were verified; details are in the
[verification record](../verification-toasts.md).

No dependencies were added. The queue is not a durable history or OS service;
the host owns limits and retention. Keep calling the stack while empty/paused.
Native modal reporting has a one-pass transition; the stack stays below modal
layers. Entry fades respect reduced motion; slide/exit effects are outside this
step. Broader platform/screen-reader acceptance remains explicitly unverified.
