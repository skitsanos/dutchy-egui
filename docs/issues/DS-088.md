# DS-088 — Split actions need a shared button composition

Status: Resolved in 1.0.28 · 2026-11-09

## Problem

Hosts hand-compose primary and menu actions, risking padding and keyboard inconsistencies.

## Remediation

Implement a token-sized SplitButton with separate named controls and the existing Dropdown behavior.
Keep APIs additive, state with the host, dependencies minimal, code modular,
and verify keyboard/accessibility, themes/scales and disabled states.

## Resolution

Added SplitButton with two named native controls, shared variants/sizes,
joined borders and controlled Dropdown alternatives. The primary and arrow
remain independent; Down/Alt+Down opens the menu, with Escape/Tab focus
behavior preserved. Disabled/busy states close alternatives; empty alternatives
disable only the arrow. Tests cover both paths, keyboard, focus and RTL-host
order. Multi-scale rendering and native example checks pass; see
[verification](../verification-command-workflow.md).
Included in the [1.0.28 release qualification](../verification-release-1.0.28.md).
