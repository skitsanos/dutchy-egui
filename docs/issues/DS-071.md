# DS-071 — Render Markdown from Dutchy tokens

Status: Resolved in 1.0.24 · 2026-11-08

## Problem

Applications need documentation, release notes and generated help inside a
Dutchy UI. A separate widget crate would introduce another styling and egui
version boundary. The implementation needs shared typography, geometry and
native links/copy while keeping the source in the host.

## Remediation

Parse with pulldown-cmark 0.13.6 (MIT, default features off: `bitflags`,
`memchr`, `unicase`; the first two were already locked)
behind a default `markdown` feature. Build a block/inline tree once per source
change and render it from repository-owned code: `Text` typography per heading
level, paragraphs as one galley with links as focusable Link widgets over
their glyph rows, square list markers and mono numbering, read-only task
boxes, accent-rule quotes and status callouts, content-sized tables that
shrink above their widest words, `Image` figures, and a new public `CodeBlock`
with language label, native copy, line numbers, host highlighting and
horizontal scrolling. Report every activated link; open HTTP(S)/mailto and
scroll to fragments by default, or report only.

## Resolution

Integrated from `origin/gedankrayze/vibrant-cerf-rat7ho` commit `684a840`;
renumbered from that branch's DS-058 to preserve main's existing ticket.
pulldown-cmark 0.13.6 was verified against its current published documentation.
Integration review also fixed nested emphasis restoration, restricted native
URL opening to the documented schemes, preserved vertical document flow in
horizontal hosts, enforced CodeBlock wrapping, and restored owned-surface ink
inside inverse Cards. Focused regressions reproduce each defect before its fix.

All 490 combined tests pass, including model, interaction, composition,
feature-profile and six Markdown image baselines. Native checks cover reported
links, anchors, heading demotion, live source edits and Copy feedback. Limits
are documented in [the guide](../markdown.md).
