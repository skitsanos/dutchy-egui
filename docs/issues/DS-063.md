# DS-063 — Grid cells justify wrapped text

Status: Resolved in 1.0.24 · 2026-11-08

## Problem

`ResponsiveGrid` lays out each row with egui's `Ui::columns`, which gives every
column a `Layout::top_down_justified(Align::LEFT)`. egui's `Label` copies the
layout's horizontal justification into its layout job, so every wrapped `Text`
and every MediaCard description inside a grid cell is fully justified: interior
lines stretch to the column width with uneven word gaps while the last line
stays ragged. The web reference never justifies copy.

Observed natively on 2026-11-08 at 1x on the Color picker page ("The host
supplies these named colors; the widget never…" stretched across the card) and
on the Media cards page descriptions. The tracked `collection-light-1x`,
`collection-dark-1_5x` and `collection-blue-2x` baselines encode the same
spacing. Any host that places Dutchy text inside `ui.columns` or another
justified layout sees the same effect.

## Remediation

Give grid cells a plain `Layout::top_down(Align::Min)` scope inside
`ResponsiveGrid` so cells keep their width without justifying text. Make `Text`
and the MediaCard description immune to host justification by laying the galley
out with justification disabled (a non-justified child layout, or painting the
galley directly) instead of inheriting it through `egui::Label`. Add a
regression that renders wrapped `Text` inside `ui.columns` and asserts that no
`Shape::Text` galley has `job.justify` set, then refresh only the collection
baselines whose word spacing changes.

## Resolution

`ResponsiveGrid` now gives each cell a plain `Layout::top_down(Align::Min)`
scope, and `Text`, MediaCard titles and MediaCard descriptions go through
`text::add_ragged`. Inside a justified layout it lays the job out with
justification off and hands the finished galley to egui's `Label`, so the
allocated rect, placement (including centered `add_sized` boxes) and
accessible name are unchanged while the lines stay ragged; non-justified
layouts take the unchanged direct `Label` path. Regressions: `grid_cells_and_dutchy_text_keep_wrapped_lines_ragged`
(`tests/layout.rs`) renders an egui label and Dutchy text inside grid cells and
`ui.columns` and asserts that no painted galley is justified;
`title_and_description_stay_ragged_inside_justified_host_layouts`
(`tests/media_card.rs`) does the same for a card inside `ui.columns`. Both failed
before the change and pass after it. The three `collection-*` baselines were
refreshed and reviewed at 1x, 1.5x and 2x; only the description word spacing
changed, and every other tracked baseline, including the `color-picker-*`
images with centered `add_sized` channel labels, is byte-identical. The layout
and MediaCard guides record the contract. Evidence for the original defect: egui 0.37 `Ui::columns_dyn`
(`Layout::top_down_justified`) and `Label::layout_in_ui`
(`layout_job.justify = ui.layout().horizontal_justify()`); native zoom of the
Color picker and Media cards pages on 2026-11-08.
