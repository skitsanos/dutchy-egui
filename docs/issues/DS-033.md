# DS-033 — Alerts and banners deviate from the live Alert component

Status: Resolved for the defects · 2026-11-07

## Problem

Compared with `src/components/Alert/index.tsx` and the banner markup in
`docs/01-design-system/components/alerts.md`:

- Tinted alert message text is the full foreground. `Alert::show`
  (`src/widgets/alert/mod.rs`) installs `override_text_color = foreground` for
  tinted surfaces and the message uses the default `Text` color. The web
  description is `text-muted-foreground`; only the title is foreground. In
  `tests/snapshots/close-light-1x-alert-hover.png` title and body share one color.
- The live component has no banner; the banner comes from the Markdown pattern,
  which is a single `text-sm font-bold uppercase tracking-wide` line with
  16/12-point padding and a right-aligned action filled with the on-primary
  color and primary text. The port paints a 16-point inset on all sides, a bold
  title plus a regular message, and a `Secondary` action (foreground fill)
  below the message, so the orange banner carries a black button
  (`tests/snapshots/surfaces-light-1x.png`, "EXPLORE"). `docs/cards-alerts.md`
  records the placement and the secondary variant as choices, not the
  inverse-filled web action.
- Status icons are simplified: the live component uses `info`, `check-circle`,
  `alert-circle`, and `x-circle`; `src/widgets/alert/icon.rs` paints a bare
  "i", a check, a triangle with a bang, and an X without circles.
- The resting dismiss glyph is the foreground at 70 % opacity
  (`IDLE_OPACITY` in `src/tokens/close.rs`); the web uses the muted-foreground
  token and switches to foreground on hover.

The warning tint uses the shared warning token instead of the component's own
hsl(45 93% 47%); that substitution is documented. The 4-point accent edge, 10 %
tint, 16-point padding, 20-point icon, and 32-point dismiss target match.

## Remediation

Install the foreground override only on banners, where the inverse color is
correct, and give tinted messages `TextColor::Muted`. Decide whether banners
adopt the single-line uppercase treatment and inverse-filled action, or record
the current layout as intentional in the guide. Consider circle-backed status
glyphs and the muted-foreground resting glyph for parity. Refresh the surface
and close-control baselines after any change.

## Resolution

Fixed in 1.0.16. Tinted alerts no longer install the foreground override: the
title keeps the surface foreground and the message uses `TextColor::Muted`,
while banners still install their inverse text color for host content. Status
glyphs are circle-backed (info, check-circle, alert-circle, x-circle, in the
icons' 24-unit proportions) and the resting dismiss glyph is the
muted-foreground token, foreground on hover; toasts keep their inverse resting
glyph. `tests/alerts.rs` reads the painted title/message colors, counts the
circle strokes and checks the resting glyph color. The banner keeps its title,
message and secondary action; `docs/cards-alerts.md` records the web's
single-line, inverse-filled action pattern as the difference. The surface and
close-control baselines were refreshed.
