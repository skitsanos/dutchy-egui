# DS-037 — Form controls do not compose with inverse surfaces, and small gaps

Status: Resolved · 2026-11-07

## Problem

Composition bug. `Field::label` (`src/widgets/forms/field.rs`) and the
checkbox/radio label painter (`src/widgets/forms/toggle.rs`) resolve their
text through `Text::layout_job`, which maps `TextColor::Foreground` straight
to `palette.foreground` and ignores `override_text_color`; only the `Text`
widget honors the override. egui's `TextEdit` does honor it, while
`src/widgets/forms/style.rs` fixes the editor fill to `palette.background`.
Inside a `CardVariant::Dark`/`Primary` card or a solid banner, which install
an inverse override (DS-006), a field therefore paints its label
foreground-on-foreground and its editor text background-on-background. The
showcase only places forms on Bordered/Muted cards, so nothing exercises it.

Smaller, undocumented differences from `src/components/{Input,Select,
Textarea,Checkbox,Radio}/index.tsx` and `src/styles/dutchy.css`:

- Horizontal text inset is 14 points (12-point margin plus the 2-point stroke
  outside it); the web is 18 (`px-4` plus a 2-pixel border). Option rows use
  the correct 16.
- `Select` opens on Enter/Space and leaves focus on the trigger (Tab reaches
  the options, as documented); the live select also opens on ArrowDown and
  focuses the first option immediately.
- Disabled fills: a disabled `Select` keeps the background fill while a
  disabled `Input` is muted; a disabled unchecked checkbox stays
  background-filled where the stylesheet uses muted.
- The textarea counter sits left-aligned between the editor and the help
  text and never changes color; the web right-aligns it on the help/error row
  and turns it destructive at the limit (host-supplied over-limit values are
  allowed, so "35 / 3" renders muted).
- The select chevron is painted in the foreground at 8×4 points; the web uses
  a muted-foreground icon. A radio label does not turn primary on hover, and
  a disabled field's label is not muted.
- The label-to-control gap renders as 12 points (see DS-034); the web is 8.
- The showcase runs the form demo's pending-validation timer and repaint
  request on every page (`examples/showcase/gallery/mod.rs`,
  `forms/state.rs`), contrary to the project's repaint policy.

Square radio indicators are documented in `docs/forms.md`. Checkbox geometry,
hover edge, focus ring, Unicode counting, password masking, read-only
semantics, and the validation rules were verified against the stylesheet and
`dutchy-form.js`.

## Remediation

Make the field and toggle labels honor the scoped override (use the `Text`
widget or read `override_text_color` before building the job) and give the
editor an inverse-aware fill, then add a test that renders a `Field` inside a
Dark card and asserts contrasting colors. Raise the inner margin to 16 points
so the 18-point inset matches. Record or align the select keyboard entry,
disabled fills, counter placement, chevron color, and hover/disabled label
colors. Gate the showcase timer on the visible page.

## Resolution

The composition bug is fixed in 1.0.16: `Field` labels and checkbox/radio
labels color their layout jobs from the scoped `override_text_color`, while
`Input`, `Textarea`, and the `Select` trigger clear the override because their
fill stays the light background. `tests/form_inverse_rendering.rs` renders a
field and checkbox on Dark and Primary cards and asserts light labels and dark
editor text from the pixels. The same leak also muted editor values inside
accordion bodies (which install a muted scoped color); the refreshed
disclosure baselines show foreground editor text. The smaller geometry and
keyboard differences listed above remain open and are tracked here.
