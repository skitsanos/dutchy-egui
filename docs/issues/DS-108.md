# DS-108 — Text composed into a List row takes the row's clicks

Status: Resolved in 1.2.0 · 2026-11-10

## Problem

In the showcase's Lists page, clicking a project name did nothing; only the
empty part of the row selected it. `show_with` content is added after the row
registers its click, and egui labels are selectable by default, so each label
sensed clicks and drags on top of the row and took its hover, click and focus.
The List tests clicked the row's center, which lay past the short labels.

## Remediation

Make row content passive the way interactive Card and MediaCard already do:
turn off selectable labels inside the row's content scope. Test a click on the
text itself, and check every showcase page for selectable text over another
clickable control so the same mistake cannot return unnoticed.

## Resolution

List rows now disable label selection for their content, so text clicks select
and hover the row. A survey of the other click surfaces found no further case:
Card and MediaCard already disable selectable text, and Segmented, Tabs, Menu,
Toolbar, table headers, the calendar, Stepper and the upload zone paint their
text instead of adding labels.

A new `click_targets` test renders every showcase page and fails when a
selectable label lies inside a clickable control's visible bounds; it reported
the six visible List rows before the fix and passes after it. A row-text click
test and a showcase click on a project name both failed before the fix and pass
now. Popups that open only after interaction (menus, Select, pickers, Command
palette) are covered by the code survey, not by the page check. All 23 local
gates pass with 674 all-feature and 435 minimal tests; native clicking was not
repeated.
