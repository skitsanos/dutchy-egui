# DS-067 — MediaCard title clearance still depends on host alignment

Status: Resolved in 1.0.24 · Priority: P2 · 2026-11-08

## Problem

DS-066 preserves the title galley's narrower wrap width, but its allocation
still inherits the host's horizontal placement. In a right-aligned host,
`text::add_measured` sets `job.halign` to `Align::Max` and the finished Label
is positioned at the full metadata row's right edge. The text therefore enters
the arrow column even though its measured width reserves that column.

Reproduced with a 200-point MediaCard inside
`ui.with_layout(Layout::top_down_justified(Align::Max), ...)` and the long title
from the existing narrow-card test. At 1x the title ends at **274.40625** while
the arrow begins at **258**, an overlap of **16.40625 points**. Left alignment
passes; Center leaves almost no gap. The existing regression covers the default
left-aligned case, so the main suite remains green.

## Remediation

Give the title an actual layout/allocation region that excludes `ICON + GAP`,
with a deliberate internal alignment, then position the arrow independently.
Preserve the general Text helper's host alignment and centered-label behavior.
Extend the clearance regression across Left/Center/Right host layouts,
justification, narrow widths, themes and display scales; check the token gap
as well as absence of overlap.

## Resolution

The title now owns a left-aligned, non-justified layout and keeps its measured
wrap width beside the independently painted arrow. The general Text helper
continues to respect host alignment. `tests/media_card_alignment.rs` checks
short and wrapped headings at 160/200/360 points in Left/Center/Right hosts,
with and without justification, across three theme/scale combinations. All
54 configurations preserve the shared token gap and accessible heading name.
The regression failed before this fix and passes afterward. The combined
suite passes.
