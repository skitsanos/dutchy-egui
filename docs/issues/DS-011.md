# DS-011 — Clarify focus cues on composite controls

Status: Resolved · 2026-11-06

## Problem

User review showed a thin focus rectangle around the selected tab, duplicating
its strong active underline. The extra rectangle made the selected state busier
than the requested Dutchy presentation.
An accordion's outward focus ring also lost its bottom edge beneath the next
row's background fill.

## Remediation

Use the active underline or segmented surface for selected tabs. Preserve the
outline when keyboard navigation targets an unselected tab, and preserve close
button/panel focus cues. Verify selection and manual activation still work.
Distinguish pointer activation from keyboard focus, retaining native focus in
both cases. Inset accordion rings so neighboring content cannot cover them.

## Resolution

Selected tabs no longer receive the extra outline. Keyboard focus remains native;
unselected targets keep their outline while the selected tab keeps its active
mark. The shared focus-visible policy hides extra rings after pointer presses;
keyboard/assistive actions restore them and hover leaves the mode unchanged.
Accordion rings now have four complete inset edges. Updated light/dark/scale
snapshots and added roving-focus, accordion-edge, and input-mode checks. This is
included in the 1.0.6 release preparation. See the
[verification record](../verification-disclosures.md).
