# DS-080 — Committed Display font licence lost its upstream line endings

Status: Resolved locally (Unreleased) · Priority: P4 · 2026-11-09

## Problem

`.gitattributes` marks `assets/fonts/*-OFL.txt` as `-text` to preserve the
upstream licence bytes, including line endings. The committed
`assets/fonts/Display-OFL.txt` is nevertheless 4402 bytes with LF endings,
while the upstream file in the development checkout is 4495 bytes with CRLF on
all 93 lines. The index still records the CRLF file's size and timestamp, so
`git status` reports the checkout clean although the blob differs. A fresh
clone, and a crate archive built from one, therefore ship the normalised copy,
while an archive built from the checkout ships the upstream bytes. The Body and
Mono licences match their blobs. Found while copying the uncommitted menus
checkout for independent review.

## Remediation

Commit the upstream bytes so clones, archives and the attribute agree, and
keep the attribute. Reconstructing the bytes from the blob avoids touching the
active checkout: appending CR to every line of the committed text must
reproduce the checkout file exactly before it is committed.

## Resolution

The blob with CR appended to every line is byte-identical to the checkout
file (`cmp` reports no difference), and that 4495-byte file is committed on
`docs/review-ds073-076`. The licence wording is unchanged. After the merge the
checkout's index matches its file, so no renormalisation is needed there.
