# DS-006 — Add cards and alerts

Status: Resolved · 2026-11-06

## Problem

Application essentials need reusable content surfaces and inline notifications.
Cards must compose existing controls without stealing their clicks, and primary/
inverted surfaces must keep text readable. Alerts need distinct severity, live
metadata, actions, and dismissal without owning application state.

## Remediation

Implement six card variants with token padding, heading/description/header/footer
helpers, and an explicitly named interactive mode. Use native egui interaction
and keyboard behavior. Add four alert severities, tinted/solid surfaces, action
and dismiss results, and an explicit focus-return target. Test interaction,
disabled-parent behavior, stable identity, and scoped appearance. Review native
and headless rendering at multiple scales and narrow widths.

## Resolution

Implemented on `ticket/cards-alerts` (1.0.2), without new dependencies. Text and
native labels inherit primary/inverted surface colors; nested cards restore
their own foreground. Display text in interactive cards no longer intercepts
activation. Explicit stable UI identities preserve focus when siblings are
inserted (the regression focuses the card's own action). Child buttons keep
their own actions.

All 44 integration tests and one doctest pass; all required Clippy configurations
pass. Reviewed light/dark rendering at 1x, 1.5x, and 2x, focus/hover, and narrow
showcase layouts. Native macOS inspection verified named card/child actions,
heading metadata, distinct alert actions, and dismissal focus restoration.
The [API guide](../cards-alerts.md)
records behavior. Source-palette contrast remains tracked in DS-003;
running screen-reader and Windows/Linux GUI testing remain outstanding.
