# DS-042 — Overlay, toast, and stepper details that drift from the references

Status: Resolved for the loop and the clock · 2026-11-07

## Problem

Overlays (`src/widgets/overlay`):

- `Memory::focus` (`memory.rs`) calls `ctx.request_repaint()` on every frame
  while entry focus is pending, and the pending flag clears only when no modal
  layer is on top or the overlay's own layer is. An overlay that never becomes
  topmost (opened beneath a host `egui::Modal`, or two overlays opened in one
  frame) repaints continuously and never receives entry focus, contrary to
  "they schedule no entrance frames once settled" in `docs/modals-drawers.md`.
  Same pattern as DS-031.
- Focus return to a toast control after an overlay closes depends on call
  order: the stack is not rendered while a modal is open, egui drops the dead
  focus, and restoration needs `read_response`, which only succeeds when the
  stack ran earlier in that pass. Undocumented.
- Web footers are `justify-end` with a 12-point gap; the showcase footers are
  left-aligned with 8-point spacing. The drawer slide has no web counterpart
  (the stylesheet defines no dialog animation); the guide does not say so.

Toasts (`src/widgets/toast`):

- The entrance fade in `render.rs` computes `(now − start) / 0.3` from the raw
  input clock with no finiteness or monotonic guard, unlike `ToastQueue`'s
  tested `delta`. A backwards step yields an invisible but interactive toast
  that requests a repaint every frame until the clock catches up; NaN
  propagates into the paint opacity. Only with host-supplied `RawInput.time`.
- The live solid toast renders "TITLE: MESSAGE" inline and vertically
  centered; the port stacks title and message top-aligned. Width is fixed at
  384 points; the live toast is content-sized (docs say a 320-point minimum).
  `docs/toasts.md` presents these as design without noting the difference.

Stepper (`src/widgets/stepper`, `src/tokens/stepper.rs`):

- Uppercase labels use 0.025 em tracking; the live standard and progress
  labels use 0.05 em. The progress variant mutes only upcoming labels where
  the live one mutes every non-current label, and its "Step X of Y" header is
  12 points against the web's 14. Compact spacing is 4+32+4 between squares
  (docs 8+32+8, live 4+20+4 then 8+32+8). The visible "STEP 2 OF 4" summary
  above the horizontal, vertical, and compact variants has no web equivalent;
  the guide presents it as a feature without flagging the departure.

Widths (448/512/672, 320/384/448), 4-point border, 50 % backdrop, header and
body geometry, close target, toast padding, 1–4 visible slots, the 5-second
default, and the documented omission of slide/exit motion all match.

## Remediation

Bound the pending-entry wait to the overlay's own layer and stop repainting
when another layer wins; document the stack-before-overlay call order or make
restoration independent of it. Guard the entrance clock like `delta`. Record or
align the footer alignment, drawer slide, toast composition/width, stepper
tracking, label muting, header size, compact spacing, and the summary line.

## Resolution

The repaint loop is fixed in 1.0.16: `Memory::focus` completes entry in the
first pass that reports the overlay's own layer as topmost, requests one repaint
when no layer is reported yet, and otherwise waits without repainting until
the covering modal closes. `tests/modal_layers.rs` opens a `Modal` beneath a
host `egui::Modal` in the same pass and asserts no repaint request while the
host modal is up and entry focus on the dialog's close control afterwards.
The entrance fade now accumulates the queue's guarded `delta` instead of
reading the raw clock, so a non-finite or backwards `RawInput.time` pauses the
fade and never hides a toast (`tests/toast_timing.rs`, entrance clock test).
The call-order dependency and the visual deviations listed above remain open.
