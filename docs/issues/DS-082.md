# DS-082 — Keyboard focus in an open menu turns invisible once the pointer moves

Status: Resolved in 1.0.26 · Priority: P2 · 2026-11-09

## Problem

DS-075 introduced input ownership: after the pointer moves, rows highlight only
under the pointer, and the keyboard-focused row paints neither the accent fill
nor a focus ring. Ownership returns to the keyboard only on the next key or
assistive event. Reproduced in the review copy: open a menu by click (the first
row is focused and painted in the primary fill), then move the pointer onto a
host control outside the popup. The focused row now paints the surface color
(`[250, 248, 245]` instead of `[249, 116, 21]` in Orange/light) while it still
has focus, and Enter activates it. WCAG 2.4.7 expects a visible focus indicator
on every focused item; a user who nudges the mouse loses track of what Enter
will do.

## Remediation

Keep a visible indicator on the focused row while the pointer owns the accent
highlight, for example the muted ancestor fill or the shared two-point focus
ring, so the pointer target and the focus target differ visibly instead of one
disappearing. Extend the polish tests to assert the focused row's paint after
the pointer leaves the popup.

## Resolution

While the pointer owns the accent highlight, the keyboard-focused row paints
the muted fill used for quiet context, so the row Enter would activate stays
marked without competing with the pointer target. Focus already follows the
pointer across rows, so the two diverge only when the pointer rests outside the
rows. `tests/menu_polish.rs` adds a test across Orange/light 1x, Orange/dark
1.5x and Blue/light 2x: with the pointer outside the popup the focused row
keeps the muted fill, and the next key returns the accent to the keyboard
target. It failed before the change (surface fill) and passes after it. After
the three fixes, `cargo fmt --all --check`, 520 all-feature and 369
minimal-feature tests, all three Clippy configurations, strict rustdoc, the
all-feature WASM check, the 1.95 MSRV check and the showcase build pass on
2026-11-09, and no rendering baseline changed. Native behavior was not
re-checked.
