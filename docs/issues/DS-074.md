# DS-074 — Native Tab exit from a nested menu can return backward

Status: Resolved locally (Unreleased) · 2026-11-09

## Problem

During DS-073 native qualification, Tab from a nested File/Export menu once
returned to the preceding inline Delete action instead of the following
Toolbar Save action. The same sequence subsequently reached Save; headless
nested/composed Tab tests passed. That leaves a real observation without an
isolated cause, so release qualification is incomplete.

## Remediation

Native tracing reproduced the inverse failure: Shift+Tab from PNG went forward
to Toolbar Save. Its Tab key carried Shift, but Shift was released before the
same frame ended. The routing read the final frame modifiers. Injecting either
disagreement deterministically reproduced wrong-direction exits in Dropdown,
MenuBar and Toolbar.

Share key-event modifier routing across all three surfaces. Consume only plain
Tab/Shift+Tab; leave modified host shortcuts available. Preserve native traversal
past the trigger, including adjacent composite controls. Also recover immediate
submenu Escape from an exact previous-pass focus snapshot, never stale focus
belonging to an external editor. Remove temporary native tracing.

## Resolution

Raw-event regressions pass across all three surfaces in both directions;
Ctrl+Tab leaves menus open. Immediate child Escape and external editor focus
regressions pass. All 14 automated gates pass (515 all-feature / 364 minimal
tests), plus archive inspection. After unlocking, native verification on
2026-11-09 confirmed default/held Tab and Shift+Tab exits, one-level Escape,
Toolbar traversal and trigger focus restoration in light/dark. Forward Tab
correctly enters the following Toolbar's remembered tool. See
[verification](../verification-menu-polish.md). No release, commit or push was
performed; version remains 1.0.25.
