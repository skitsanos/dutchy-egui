# DS-057 — Give the color-picker arrow consistent trailing space

Status: Resolved in 1.0.22 · 2026-11-08

## Problem

The ColorPicker chevron ends only 8 logical points from its right edge. It
looks crowded beside existing controls with padded trailing slots. The hex
label also needs to reserve space when the arrow moves inward.

## Remediation

Move the chevron 8 points left, using the shared 16-point spacing token for
its trailing inset. Derive the text boundary from the arrow position with a
12-point label gap. Keep control heights, interaction targets and popup
behavior intact. Review the existing Select and accordion geometry rather
than applying one inset to controls with different structural padding.

Inspect a live reference application for picture cards, sort dropdown and
search. Record measured control padding, independent card actions and native
component opportunities.

## Resolution

The arrow and text now reserve the intended space. Reviewed the three updated
local color-picker baselines at 1x, 1.5x and 2x, the showcase's three control
sizes, and the narrow popup. Existing tracked baselines are unchanged.

All required checks passed: formatting, 421 all-feature tests, 314 tests without
defaults and the three Clippy configurations with warnings denied. The native
showcase build, rustdoc with warnings denied and both WASM feature configurations
also passed.
No dependency change. Included in repository release 1.0.22 after repeated
release qualification.
