# DS-013 — Make close controls visibly interactive and align alert dismissal

Status: Resolved · 2026-11-06

## Problem

User review found missing hover feedback on alert and tag close buttons, with
only subtle glyph-color feedback on tab close buttons. The alert X also appeared
farther from the right edge than from the top.

A geometry regression reproduced the cause: the frameless empty egui button
allocated a **0x32-point** response. Its custom X extended outside that response,
leaving a poor pointer target and excess visible right spacing.

## Remediation

Use an explicit compact square response for alert dismissal. Share token-based
close painting across alerts/banners, tabs, and removable tags: a flat hover
surface, stronger pressed surface, emphasized glyph, pointing cursor, and native
keyboard focus. Preserve names, disabled behavior, independent actions, and
application-owned removal.

## Resolution

Alerts now allocate a **32x32-point** close target, **16 points** from both the top
and right edges. The centered 16-point glyph has equal 24-point visual insets.
This holds for tinted alerts and solid banners at 280- and 760-point widths.
Pointer activation near the target's corner works, not just on the glyph.

All close controls show hover/pressed feedback without early activation;
disabled controls do not highlight or activate. Tab close hover does not select
the tab. Keyboard behavior and focus restoration remain covered by existing
interaction checks. Shared painting and geometry remain modular, without new
dependencies or a package-version change beyond the 1.0.7 work.

Twelve focused light/dark/scale baselines, corrected surface baselines, full Rust
checks, and native macOS interaction review pass. Native execution was
macOS-only, without an active screen reader.
