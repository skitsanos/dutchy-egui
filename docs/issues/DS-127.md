# DS-127 — MultiSelect results moved when a Chip row appeared

Status: Resolved in 1.10.1 · 2026-11-11

## Problem

MultiSelect drew its Chips above the query. The first choice from an empty
selection added a Chip row and pushed the query and the open results down by
40 points, so the pointer rested on a different result, or on the query, for
the next click. Every further wrap of the Chips repeated the jump, which in a
narrow filter panel happened after one or two choices.

## Remediation

Draw the Chips after the query. The popup stays anchored to a query that
choices cannot move.

## Resolution

Chips now follow the query in layout and Tab order. Open results cover them;
the list's check marks show the selection meanwhile, and the Chips are
reachable by pointer once the popup closes. Removing a Chip still closes the
popup and returns focus to the query.

A test accepts two choices in a 220-point-wide control, where the second Chip
wraps, and checks that the query and result rectangles stay identical; it
failed before the change with the query 40 points lower. Light 1× and dark 2×
renders show the Chips under the query and under the open results. Backspace
in an empty query still does not remove a Chip, and the native window was not
exercised.
