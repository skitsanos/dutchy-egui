# DS-077 — DutchyTodo example application and shared example scaffolding

Status: Resolved in 1.0.26 · 2026-11-08

## Problem

The showcase proves components one page at a time. Nothing shows the library
composing under application-owned state: a store, keyboard flows across
controls, overlays that return focus, undo through toasts and import/export.
The [example applications plan](../example-applications.md) sequences
DutchyTodo first, with scaffolding every later example reuses; without it the
roadmap has no evidence of which gaps a real application hits.

## Remediation

Add `examples/support/` (theme switcher, header, sidebar and status-strip
frames, a seeded SplitMix64 generator with fictional people, and capture hooks
for native checks) included with `#[path]`, and `examples/dutchy_todo/` as a
`[[example]]` with `test = true`: a keyed in-memory store, a tab-separated line
format for import and export (no new dependency), projects with open-task
Badges, focusable task rows with Checkbox, priority and due Badges, Drawer
editing with DatePicker and a Segmented priority, a Segmented filter,
SearchInput, compact Stats and completion Progress, an EmptyState per filter,
Toast undo for complete, delete, project deletion and import, Kbd hints in the
status strip and a Modal confirmation before deleting a project. Keyboard: `N`
creates, Enter edits, Space toggles, Delete removes, Escape closes, Up/Down
move between rows and focus returns to the row. Tests live inside the example.

## Resolution

Implemented as described. The example's 24 tests (store, format, thirteen
keyboard flows and two baselines) run under `cargo test --all-features`; the
five gates and the native frames at 1x, 1.5x and 2x in both modes are in
[the verification record](../verification-dutchy-todo.md). Decisions that
differ from the plan are noted in the plan document.

Library gaps the example surfaced, for the [roadmap](../component-roadmap.md):

- **List rows.** Roving arrows, Enter/Space/Delete handling, focus locking and
  the row surface are hand-written in `row.rs`; the workbench **List** would
  own them. Checkbox is always a tab stop, so every row has two.
- **Overlay entry focus.** `OverlayOptions::initial_focus` needs an actual egui
  id, but Dutchy inputs derive theirs inside the body, so the editor requests
  focus from the body with a one-frame flag.
- **Dialog presets and shortcuts.** The confirmation is a Modal with a
  hand-built footer; `N` is bound by the host behind
  `Context::text_edit_focused` and Kbd chips are decorative. The planned
  confirm preset and command registry would own both.
- **StatusBar and ThemePicker.** The support strip and switcher are stand-ins.
- **Segmented.** Below its natural width it shrinks until labels overlap
  instead of reporting a minimum or wrapping; the toolbar measures the control
  and stacks the row itself.
- **Text.** No single-line or truncating mode, so the status strip lays out its
  own galleys; Button truncates long project names at full width.
- **Scroll fade.** egui 0.37 paints a 20-point gradient over clipped scroll
  content (`Style::spacing.scroll.fade`) and `Theme::style` does not zero it,
  so Dutchy scroll areas, the showcase included, show gradients. The support
  theme zeroed it for the examples; the library theme now does (DS-078) and
  1.0.26 removed the example override.
- **Dates and done styling.** `Date` has no short display form and there is no
  strikethrough treatment; the row slices `month_name` and uses the muted color.
