# DS-024 — Controlled file selection, drops and transfer rows

## Problem

The advanced milestone had no file selection/drop surfaces or reusable transfer
rows. The web pattern combines a dashed target, compact picker input, metadata
limits, removable files and progress/errors. egui 0.37 now exposes lazy dropped
file handles, so earlier struct-based integration ideas were obsolete.

## Remediation

Implement repository-owned `FileUpload`, `FileRules` and `FileList` modules using
shared tokens and native egui semantics. Return picker/drop and keyed action
requests; keep selection, metadata inspection, bytes and transfers in the host.
Consume a drop once per viewport/frame only over an enabled, visible, unobscured
target; respect modal/clip checks and discarded layout passes.

Share pure extension/MIME/size/count validation across both input paths. Preserve
unknown metadata explicitly. Add wrapped keyed rows for ready, determinate,
indeterminate, complete and failed states, with remove/cancel/retry, shared close
feedback and focus after actual host removal.

Add a native picker/background-metadata showcase with explicit local transfer
simulation. Verify current rfd 0.17.2 and keep it development-only. Split showcase
page definitions and widget painting from interaction logic to retain small files.

## Resolution

Implemented locally for 1.0.14, after 1.0.13 was pushed as `c4a728d`. Policy,
drop routing, keyboard/focus/action, host validation/simulation and narrow/theme/
scale rendering tests cover the public API. Native macOS picker selection,
focus return, simulated failure/retry and completion were observed. No new runtime
dependency or vendored widget implementation was added.

Physical OS cross-window drag delivery, browser picker/runtime and Windows/Linux
GUI acceptance remain separate from deterministic egui input tests. Transfers,
content verification and folder traversal remain host-owned. See
[verification](../verification-file-uploads.md).

The new post-push rule was applied to 1.0.13: 81 GiB of generated artifacts and
13 unused merged local branches were removed. Only the active worktree remained;
the unmerged Renovate branch and current edits were preserved. Development then
recreated the artifacts needed for 1.0.14 verification. No 1.0.14 push is authorized.
