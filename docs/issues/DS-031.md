# DS-031 — Command palette spins repaints and defers a focus jump behind other modals

Status: Resolved · 2026-11-07

## Problem

`CommandPalette::show` (`src/widgets/command_palette.rs`, closed branch) marks
`restore_pending` when the palette closes with its input focused, then on every
later frame checks `top_modal_layer()`: if any modal layer is present it skips
the restore and calls `ctx.request_repaint()` unconditionally. The check does
not distinguish the palette's own layer from a host modal. In the common flow
where a palette command opens a `Modal` or `Drawer`, the palette therefore
requests a repaint every frame for as long as that dialog is open, and when the
dialog closes it moves focus back to the control that was focused before the
palette opened, competing with the dialog's own deferred focus return
(`src/widgets/overlay/memory.rs`). The project's repaint policy allows repaints
only while visible animation needs them, and `docs/menus-dropdowns.md` documents
neither the continuous repaint nor the late focus jump.

Related, lower severity: `SearchKeys::take` (`src/widgets/search/keys.rs`)
consumes Escape whenever the search is open, before egui's topmost-modal check,
and `Dropdown` (`src/widgets/dropdown.rs`) closes on any Tab press and consumes
any Escape while open regardless of where focus is. A host surface stacked above
an open palette or dropdown would lose its Escape.

## Remediation

Record which modal layer belonged to the palette and wait only for that layer
(or at most one pass, matching the documented one-pass transition). Drop the
pending restore when another modal takes over, or when focus has moved to a
different enabled widget, instead of repainting until it clears. Consume Escape
and Tab only while the palette's or dropdown's own layer is topmost, or while the
search input or a menu row has focus. Add a regression that opens a host
`Modal` from a palette action and asserts no repaint request after the
palette's closing frame and no focus change when the dialog closes.

## Resolution

Fixed in 1.0.16. `CommandPalette::show` now distinguishes the modal layers it
sees while a restore is pending: no layer restores focus immediately, the
palette's own layer (reported for one more pass) waits with a single repaint
request, and any other layer abandons the restoration because that modal owns
focus. `tests/modal_layers.rs` opens a host `egui::Modal` in the frame the
palette closes and asserts that no repaint is requested afterwards and that
focus does not return to the opener when the host modal closes. The Escape and
Tab consumption noted above is unchanged and remains a documented limit.
