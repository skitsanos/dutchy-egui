# DS-120 — Path input with host-owned browsing

Status: Resolved (unreleased) · 2026-11-11

## Problem

Applications need to let users type or browse for a single file, folder, or
save destination. The existing FileUpload component serves file collections
and drop zones.

## Remediation

Compose the native text editor and Browse button with shared control sizes.
Return a typed request so the host can choose a picker and apply its result.
Show all three modes in Showcase using its existing `rfd` dev-dependency.
Stop read-only editors from reporting a change when text is pasted into them.

## Resolution

PathInput returns the editor and Browse responses alongside an optional
`OpenFile`, `OpenFolder` or `SaveFile` intent. The host owns validation,
dialog handling, and filesystem operations. Showcase applies a selected path
to the corresponding field and restores Browse focus after the dialog closes.
Browse moves below the editor once the editor would be narrower than the
button; the first rule waited until the editor was narrower than its own
height, leaving room for about three characters.

egui marked a paste into a read-only buffer as a change. Input now clears that
flag, which also covers Textarea and the controls built on Input.

Tests cover pointer, keyboard and assistive activation, read-only and disabled
states, the stacking threshold at every size, identity and focus through
reflow, and rendering in light 1× and dark 2×. A forms test fails without the
paste fix, with both Input and Textarea reporting a change.
On macOS, all three pickers populated their fields. Cancelling Save As kept the
previous value and returned focus. Choosing the destination created no file.
