# DS-128 — RangeSlider

Status: Resolved (unreleased) · 2026-11-12

## Problem

Filters over numbers, such as a price or a duration, need a lower and an upper
bound. Slider edits one value, so hosts had to stack two sliders and keep them
in order themselves.

## Remediation

Wrap egui's range slider the way Slider wraps egui's slider, and paint the
Dutchy rail, fill and square handles from one shared module. Name each handle
for assistive technology without showing a text label, and let hosts replace
those names.

## Resolution

RangeSlider edits two host values on the Slider rail with the primary fill
between the handles. The nearer handle follows a press and keeps the pointer
for the whole drag. The handles meet but never cross, and `min_separation`
keeps them apart. Each handle is a tab stop and a Slider node bounded by the
other handle; the rail is a named Group. Slider and RangeSlider now share
`slider_rail.rs` for the rail, fill, handle geometry, focus ring and label
column.

While testing the label column, a labelled Slider turned out to run 8 points
past its width: item spacing was added on both sides of the 12-point gap. The
shared row now clears item spacing, so rail, gap and column fill the width
exactly and the label starts 12 points after the rail.

Tests cover handle semantics and bounds, keyboard stepping and Tab order,
separation, clamping of host values, press and drag, paint geometry, the focus
ring, disabled and covered states, sibling insertion, Field naming and custom
handle names. Baselines for light 1×, dark 1.5× and green 2× show the control;
focused, hovered, collapsed, disabled and 240-point-wide states were also
rendered and inspected in light 1×, dark 2× and light 1.5×.

Limits: horizontal and linear only. The two handle IDs come from egui's
internal "low" and "high" salts, so an egui upgrade must re-run these tests.
A Field label click does not focus a handle. When the handles coincide, egui
draws the high handle on top, so the low handle's hover and focus fill is
hidden; its focus ring still shows. The native window was not exercised.
