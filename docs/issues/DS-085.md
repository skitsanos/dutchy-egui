# DS-085 — Todo Undo actions can modify a replacement import

Status: Resolved in 1.0.27 · Priority: P2 · 2026-11-09

## Problem

Import replaces the task store but retains existing Undo toasts. Their numeric
IDs can refer to different imported records. The 1.0.26 source probe changed an
unrelated imported task from done to open with an old completion Undo; an old
deletion Undo replaced it with the original task. Undo-import has the same
boundary when restoring the previous store.

## Remediation

Bind Undo requests to an opaque store-history identity. Invalidate requests and
clear queued notifications whenever import or undo-import replaces the store,
including actions already returned by the UI. Reset editor, confirmation and
focus bindings that reference old records. Keep the current import's own Undo
usable and test repeated replacements and stale payloads.

## Resolution

Implemented in the example's history and replacement operations. Regressions
exercise stale completion, task deletion and project deletion; Undo-import;
successive imports; and failed imports preserving valid history. All 33 Todo
tests and the full 14-gate matrix pass. Native macOS import and Undo-import
restore the expected records; no old notifications return. See the
[verification record](../verification-todo-import-safety.md) and
[release qualification](../verification-release-1.0.27.md).
